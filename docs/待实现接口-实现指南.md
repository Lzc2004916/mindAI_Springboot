### 0.3 全项目通用约定（写代码前先记住这 5 条）

**① 统一响应体 `Result<T>`**（`common/Result.java`）

```json
{ "code": "200", "msg": "操作成功", "data": { } }
```

失败用 `Result.error(code, msg, data)`，业务异常直接 `throw new BusionessException("提示语")`，由 `GlobarExceptionHandler` 兜住。

> **第 7 章会给 `Result` 再加 `success` / `message` 两个字段**（前端样例里要求的），
> 属于纯新增，不影响老接口。加了之后返回体形如：
> `{ "code":"200", "msg":"操作成功", "success":true, "message":"操作成功", "data":{ } }`

**② 鉴权：请求头 `token`，裸 JWT（不带 Bearer）**

这是**当前代码的实际行为**，务必注意：

```java
// JwtTokenUtil.extractTokenFromRequest —— 写死读 "token" 头
String token = request.getHeader("token");
```

而 `application.yml` 里配的是 `header: Authorization` + `token-prefix: "Bearer "` —— **这两个配置目前完全没被使用**。

> ⚠️ 联调前必须和前端定死是哪一种。改法见 [附录 A.1](#a1-jwttokenutil-不读-yaml-配置)，改完前端就能用标准的 `Authorization: Bearer xxx`。

**③ 登录态用户 ID 从 AOP 拿**

```java
@GetToken                          // 标注在 Controller 方法上，触发切面解析 token
Long userId = Token_Aspect.getUserId();
```

**④ 管理员判定**

```java
// 方式一：方法级注解（Spring Security 的 @PreAuthorize）
@PreAuthorize("hasRole('2')")      // 对应 User.userType = 2，内部会拼成 ROLE_2

// 方式二：代码内分支（适合"管理员看全部、用户看自己"这类同一接口两种行为）
boolean isAdmin = AuthUtil.isAdmin();
```

注意区分：**`@PreAuthorize` 不满足直接 403；`AuthUtil.isAdmin()` 是你自己在代码里分流。**
管理端专用接口用①，用户端/管理端共用接口用②。

**⑤ 分页已就绪**

`MybatisPlusConfig` 里已注册 `PaginationInnerInterceptor`，直接用 `new Page<>(pageNum, pageSize)` 即可。
返回类型是 MyBatis-Plus 的 `Page<T>`，前端拿 `records`（数据）+ `total`（总数）。

### 1.2 实现思路：一次查全表 + 内存组装

你的第一反应可能是「递归查库：先查一级，再逐个查它的子级」——**别这么写**。
分类表通常只有几十行，但递归查库会产生 N+1 次查询（1 次查一级 + N 次查二级 + …），分类一多就明显变慢。

正确做法：**一条 SQL 把全表查出来，在 Java 内存里按 `parentId` 分组组装成树**。

```
数据库返回（平铺）                 内存按 parentId 分组              递归挂children
┌ id=1 parentId=0 ─┐             0 → [1, 2]                    1
├ id=2 parentId=0 ─┤    ==>      1 → [3, 4]         ==>        ├─ 3
├ id=3 parentId=1 ─┤             2 → []                        └─ 4
├ id=4 parentId=1 ─┤             3 → []                        2
└ id=5 parentId=3 ─┘             4 → []
                                 3 → [5]
```

### 1.3 代码

#### ① 新建 VO：`response/CategoryTreeVO.java`

```java
package com.lzc.mindaispringboot.response;

import lombok.AllArgsConstructor;
import lombok.Builder;
import lombok.Data;
import lombok.NoArgsConstructor;

import java.util.ArrayList;
import java.util.List;

/**
 * 分类树节点。
 * 只保留前端需要的字段，不直接返回 KnowledgeCategory 实体——
 * 实体里的 description / createdAt / updatedAt 对树形下拉毫无用处，还会让 JSON 变臃肿。
 */
@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class CategoryTreeVO {
    private Long id;
    private String categoryName;
    private String categoryCode;
    private Integer sortOrder;

    /** 子分类；没有子级时是空数组（不要返回 null，前端 v-for 会报错） */
    @Builder.Default
    private List<CategoryTreeVO> children = new ArrayList<>();
}
```

> 💡 `@Builder.Default` 是必需的：Lombok 的 `@Builder` 会忽略字段初始值，不加的话 `new CategoryTreeVO(...)` 通过 builder 创建时 `children` 会是 `null`。

#### ② 改 Service：`service/KnowledgeCategoryService.java`

在现有 `getEnabledCategories()` 后面追加两个方法：

```java
package com.lzc.mindaispringboot.service;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.lzc.mindaispringboot.entity.KnowledgeCategory;
import com.lzc.mindaispringboot.mappper.KnowledgeCategoryMapper;
import com.lzc.mindaispringboot.response.CategoryTreeVO;
import jakarta.annotation.Resource;
import org.springframework.stereotype.Service;

import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

@Service
public class KnowledgeCategoryService {
    @Resource
    private KnowledgeCategoryMapper categoryMapper;

    /** 返回所有"启用"的分类（平铺列表，按 sortOrder 升序）。—— 原有方法，保持不变 */
    public List<KnowledgeCategory> getEnabledCategories() {
        LambdaQueryWrapper<KnowledgeCategory> queryWrapper = new LambdaQueryWrapper<>();
        queryWrapper.eq(KnowledgeCategory::getStatus, 1);
        queryWrapper.orderByAsc(KnowledgeCategory::getSortOrder);
        return categoryMapper.selectList(queryWrapper);
    }

    /** 分类树：一次查全表，内存组装 */
    public List<CategoryTreeVO> getCategoryTree() {
        // 1. 只查启用状态，按 sortOrder 升序（保证同级顺序稳定）
        LambdaQueryWrapper<KnowledgeCategory> qw = new LambdaQueryWrapper<>();
        qw.eq(KnowledgeCategory::getStatus, 1);
        qw.orderByAsc(KnowledgeCategory::getSortOrder);
        List<KnowledgeCategory> all = categoryMapper.selectList(qw);
        if (all.isEmpty()) return new ArrayList<>();

        // 2. 实体 → VO，并按 parentId 分组
        //    用 LinkedHashMap 而不是 HashMap：保证分组的遍历顺序 = 数据库返回顺序
        Map<Long, List<CategoryTreeVO>> groupByParent = new LinkedHashMap<>();
        for (KnowledgeCategory c : all) {
            // parentId 可能是 null（表结构允许），统一成 0 表示"一级分类"，避免后面 map.get(null) 出岔子
            Long parentId = c.getParentId() == null ? 0L : c.getParentId();
            groupByParent.computeIfAbsent(parentId, k -> new ArrayList<>()).add(toVO(c));
        }

        // 3. 从一级分类（parentId = 0）开始递归挂载子级
        return buildChildren(0L, groupByParent);
    }

    /** 递归：把 groupByParent 中 parentId 对应的节点挂上它们各自的 children */
    private List<CategoryTreeVO> buildChildren(Long parentId, Map<Long, List<CategoryTreeVO>> groupByParent) {
        List<CategoryTreeVO> nodes = groupByParent.get(parentId);
        if (nodes == null || nodes.isEmpty()) return new ArrayList<>();
        for (CategoryTreeVO node : nodes) {
            node.setChildren(buildChildren(node.getId(), groupByParent));
        }
        return nodes;
    }

    private CategoryTreeVO toVO(KnowledgeCategory c) {
        return CategoryTreeVO.builder()
                .id(c.getId())
                .categoryName(c.getCategoryName())
                .categoryCode(c.getCategoryCode())
                .sortOrder(c.getSortOrder())
                .children(new ArrayList<>())   // 先给空数组，后面由 buildChildren 填充
                .build();
    }
}
```

### 1.4 两个容易踩的坑

| 坑 | 说明 |
|---|---|
| **死循环** | 如果数据库里出现 `A.parentId = B` 且 `B.parentId = A`（或自己指向自己），递归会栈溢出。分类由后台录入一般不会，但**建议后台新增分类时禁止把父级选成自己或自己的子孙** |
| **`parentId` 为 null** | 表里 `parent_id` 允许 null，实体里也是 `Long` 包装类。上面代码已用 `parentId == null ? 0L : parentId` 兜住，不要漏掉这行 |

### 3.2 整体流程

```
Controller 接收 MultipartFile
   ↓

④ 落库：sys_file_info 插一条记录
```

### 3.7 Service：`service/FileService.java`

```java
package com.lzc.mindaispringboot.service;

import cn.hutool.core.io.FileUtil;
import cn.hutool.core.util.StrUtil;
import com.lzc.mindaispringboot.entity.SysFileInfo;
import com.lzc.mindaispringboot.exception.BusionessException;
import com.lzc.mindaispringboot.mappper.SysFileInfoMapper;
import com.lzc.mindaispringboot.response.FileUploadVO;
import jakarta.annotation.Resource;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;
import org.springframework.web.multipart.MultipartFile;

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.nio.file.StandardCopyOption;
import java.time.LocalDate;
import java.time.LocalDateTime;
import java.util.List;
import java.util.Locale;
import java.util.UUID;

@Service
public class FileService {

    /** 单文件上限 10MB（跟 yml 里保持一致，双保险） */
    private static final long MAX_SIZE = 10 * 1024 * 1024L;

    /** 扩展名白名单：只允许图片和常见文档，禁止上传 exe/sh 等可执行文件 */
    private static final List<String> ALLOWED_EXT = List.of(
            "jpg", "jpeg", "png", "gif", "webp", "bmp",
            "pdf", "txt", "doc", "docx", "xls", "xlsx", "ppt", "pptx"
    );

    @Value("${file.upload-dir}")
    private String uploadDir;

    @Resource
    private SysFileInfoMapper sysFileInfoMapper;

    public FileUploadVO upload(MultipartFile file, String businessType, String businessId,
                               String businessField, Boolean isTemp, Long userId) {
        // ① 校验：文件不能为空
        if (file == null || file.isEmpty()) {
            throw new BusionessException("请选择要上传的文件");
        }
        // ② 校验：大小
        if (file.getSize() > MAX_SIZE) {
            throw new BusionessException("文件大小不能超过 10MB");
        }
        // ③ 校验：扩展名白名单
        String originalName = file.getOriginalFilename();
        String ext = getExt(originalName);
        if (!ALLOWED_EXT.contains(ext)) {
            throw new BusionessException("不支持的文件类型：" + ext);
        }

        try {
            // ④ 生成存储路径：根目录 / 年 / 月 / 日 / UUID.ext
            //    按日期分目录，避免单个目录塞几万个文件（Windows 下目录文件多了打开会卡）
            String datePath = LocalDate.now().toString().replace("-", "/");   // 2026/09/17
            String relative = datePath + "/" + UUID.randomUUID() + "." + ext;
            Path target = Paths.get(uploadDir).resolve(relative);

            // ⑤ 目录不存在就创建（Files.copy 不会自动建父目录，漏了这步会报 NoSuchFileException）
            Files.createDirectories(target.getParent());

            // ⑥ 写磁盘。REPLACE_EXISTING 在 UUID 场景下基本用不到，但写上更稳
            try (var in = file.getInputStream()) {
                Files.copy(in, target, StandardCopyOption.REPLACE_EXISTING);
            }

            // ⑦ 落库
            SysFileInfo info = SysFileInfo.builder()
                    .originalName(originalName)
                    .filePath("/files/" + relative)          // 对外访问路径
                    .fileSize(file.getSize())
                    .fileType(resolveFileType(ext))
                    .businessType(businessType)
                    .businessId(businessId)
                    .businessField(businessField)
                    .uploadUserId(userId)
                    .isTemp(Boolean.TRUE.equals(isTemp) ? 1 : 0)
                    .status(1)
                    .createTime(LocalDateTime.now())
                    // 临时文件给 24 小时有效期，方便后续定时清理
                    .expireTime(Boolean.TRUE.equals(isTemp) ? LocalDateTime.now().plusHours(24) : null)
                    .build();
            sysFileInfoMapper.insert(info);

            // ⑧ 返回
            return FileUploadVO.builder()
                    .id(info.getId())
                    .originalName(info.getOriginalName())
                    .filePath(info.getFilePath())
                    .fileSize(info.getFileSize())
                    .fileType(info.getFileType())
                    .businessType(info.getBusinessType())
                    .build();
        } catch (IOException e) {
            throw new BusionessException("文件上传失败：" + e.getMessage());
        }
    }

    /** 取小写扩展名，取不到返回空串 */
    private String getExt(String filename) {
        if (StrUtil.isBlank(filename)) return "";
        int idx = filename.lastIndexOf('.');
        return idx < 0 ? "" : filename.substring(idx + 1).toLowerCase(Locale.ROOT);
    }

    /** 把扩展名归成表里的 file_type 大类 */
    private String resolveFileType(String ext) {
        return switch (ext) {
            case "jpg", "jpeg", "png", "gif", "webp", "bmp" -> "IMG";
            case "pdf" -> "PDF";
            case "txt" -> "TXT";
            case "doc", "docx" -> "DOC";
            case "xls", "xlsx" -> "XLS";
            default -> "OTHER";
        };
    }
}
```

### 3.9 静态资源映射：`config/WebMvcConfig.java`（新建）

**这一步不做，上传成功也访问不了。** 磁盘上的文件在 Spring Boot 眼里不是静态资源，必须显式把 URL 映射到目录：

```java
package com.lzc.mindaispringboot.config;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.ResourceHandlerRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class WebMvcConfig implements WebMvcConfigurer {

    @Value("${file.upload-dir}")
    private String uploadDir;

    /** 访问前缀，与 FileService 里写的 "/files/" 对应 */
    @Value("${file.access-prefix}")
    private String accessPrefix;

    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        // "/files/**" → 磁盘目录。注意结尾必须带 "/"，否则路径拼接会出错
        registry.addResourceHandler(accessPrefix)
                .addResourceLocations("file:" + uploadDir);
    }
}
```

### 3.10 放行 `/files/**`：`config/SecurityConfig.java`

**这一步不做，访问图片会被 Spring Security 拦成 401。** 在 `PUBLIC_MATCHERS` 数组里加一行：

```java
    private static final String[] PUBLIC_MATCHERS = {
            "/",
            "/api/test",
            "/api/user/login",
            "/api/user/add",
            "/files/**",          // ← 新增：上传的文件允许匿名访问
    };
```

> 为什么文件要放行？前端 `<img src="...">` 发起的请求**不会自动带 token 头**，带了也会被浏览器限制。图片又不是敏感数据，直接放行最简单。

### 3.11 补一个异常处理（可选但强烈建议）

文件超过 yml 里配的 `max-file-size` 时，Spring 抛的是 `MaxUploadSizeExceededException`，**不会被你现有的 `GlobarExceptionHandler` 捕获**，前端会收到一个 HTML 错误页而不是 JSON。

在 `GlobarException/GlobarExceptionHandler.java` 里追加：

```java
    // 文件超过大小限制

    public Result<String> handleMaxUploadSizeExceededException(MaxUploadSizeExceededException e) {
        return Result.error(ResultCode.FILE_SIZE_EXCEEDED.getCode(),
                            ResultCode.FILE_SIZE_EXCEEDED.getMessage(),
                            "最大支持 10MB");
    }
```

对应 import：

```java
import org.springframework.web.multipart.MaxUploadSizeExceededException;
```

（`ResultCode.FILE_SIZE_EXCEEDED` 已经在你的枚举里了，值为 `5004 / 文件大小超过限制`，直接用。）

## 4. 情绪日记的 AI 分析（对齐前端契约）

> 本章已按你贴出的前端 Vue 代码**逐字段对齐**，`aiData` 里的每一个 key 都有对应实现。
> 数据来源：前端在情绪日志详情弹窗里读的是 `row.aiEmotionAnalysis`，即 `emotion_diary.ai_emotion_analysis` 列。

### 4.1 前端契约（从你的 Vue 代码反推）

你的 `viewSessionDetail` 里做了 `JSON.parse(row.aiEmotionAnalysis)`，之后 `aiData` 被这样消费：

| 前端显示 | JSON key | 类型 | 取值 / 处理逻辑 |
|---|---|---|---|
| 主要情绪（标签） | `primaryEmotion` | String | `getAiEmotionTagType`：快乐/平静/兴奋/满足 → 绿或橙；愤怒/恐惧 → 红；悲伤/沮丧 → 灰；焦虑/压力 → 橙。匹配不上 → `info` 灰 |
| 情绪强度（进度条） | `emotionScore` | Number 0~100 | `getEmotionScoreColor`：≥80 红 `#f56c6c`；≥60 橙 `#e6a23c`；≥40 灰 `#909399`；<40 绿 `#67c23a` |
| 风险等级（标签） | `riskLevel` | **Integer 0/1/2/3** | 0→正常(绿) 1→关注(灰) 2→预警(橙) 3→**危机**(红) |
| 情绪性质（标签） | `isNegative` | **Boolean** | `true` →「负面情绪」红；`false` →「正面情绪」绿 |
| 专业建议（单行） | `suggestion` | String | 直接展示，空则显示"无" |
| 风险描述（单行） | `riskDescription` | String | 直接展示 |
| 改善建议（列表） | `improvementSuggestions` | Array\<String\> | `v-for` 渲染，空数组显示"无" |

**响应 JSON 示例（必须长这样）**

```json
{
  "primaryEmotion": "焦虑",
  "emotionScore": 62,
  "riskLevel": 2,
  "isNegative": true,
  "suggestion": "试着把让你焦虑的事情拆成可以执行的小步骤",
  "riskDescription": "存在持续性焦虑，暂无自伤倾向",
  "improvementSuggestions": ["每天 10 分钟呼吸练习", "把焦虑事件按可控程度分类", "和信任的人聊一次"]
}
```

### 4.2 四个必须注意的地方（跟我之前暂定的不一样）

| # | 我之前暂定 | 你前端实际 | 后果 |
|---|---|---|---|
| 1 | `riskLevel` 是字符串「正常/关注/预警/**紧急**」 | **整数 0/1/2/3**，文案第四档是「**危机**」 | 按暂定值写，前端 `riskTextMap[2]` 找不到 → 显示「未知风险等级」，颜色掉 `info` |
| 2 | `emotionNature` 是「正面/中性/负面情绪」三个值 | **`isNegative` 布尔值**，只有 true/false | 没有"中性"这一档，中性只能归 `false`（显示正面情绪） |
| 3 | 字段叫 `dominantEmotion` / `emotionIntensity` / `professionalAdvice` | `primaryEmotion` / `emotionScore` / `suggestion` | 名字全不对，前端读到 `undefined`，卡片七项全空 |
| 4 | `dominantEmotion`（列表页那列）和 AI 的「主要情绪」是同一个映射 | **两个映射表不一样** | 见下方说明 |

**关于第 4 点**，你前端其实有两张「主要情绪」映射表：

```js
// 列表页那列，读的是日记自带字段 dominantEmotion（7 个值）
getEmotionTagType:  快乐 / 开心 / 平静 / 兴奋 / 愤怒 / 悲伤 / 焦虑

// AI 卡片里，读的是 primaryEmotion（10 个值）
getAiEmotionTagType: 快乐 / 平静 / 兴奋 / 满足 / 愤怒 / 悲伤 / 焦虑 / 恐惧 / 沮丧 / 压力
```

所以提示词里要把 `primaryEmotion` 限定在那 **10 个值**里，这样标签颜色全部对得上。

**关于 `emotionScore` 的语义**：你的颜色函数里**分数越高越红**（≥80 红色）。
所以这个分数不能是"开心程度"，否则一个人很开心（90 分）会显示成红色危险条。
建议定义为**情绪强度 + 负面程度**的综合分：越强烈、越负面 → 分数越高。
（如果你本意是"强度"而不含正负，那颜色函数要反过来写，告诉我我再调。）

### 4.4 结构定义（为什么必须用 `record`）

```java
package com.lzc.mindaispringboot.AiService;

import java.util.List;

public class StructOutPut {
    // ... 原有 StreamChatSession / EmotionAnalysis 保持不变 ...

    /**
     * 情绪日记的 AI 分析结果 —— 字段名严格对齐管理端「AI情绪分析结果」卡片。
     *
     * 必须用 record，不能用 class + @Data：
     * 字段 isNegative 如果用 Lombok @Data 生成，getter 会变成 getIsNegative()/isNegative()，
     * Jackson 序列化出来的 key 可能是 "negative" 而不是 "isNegative"，前端就取不到值。
     * record 的 component 名就是 JSON key，不会走 getter 命名规则。
     */
    public record DiaryEmotionAnalysis(
            String primaryEmotion,              // 主要情绪：快乐/平静/兴奋/满足/愤怒/悲伤/焦虑/恐惧/沮丧/压力
            Integer emotionScore,               // 情绪强度 0~100（越高越负面/越强烈）
            Integer riskLevel,                  // 风险等级：0正常 1关注 2预警 3危机
            Boolean isNegative,                 // 是否负面情绪
            String suggestion,                  // 专业建议（一句话）
            String riskDescription,             // 风险描述（一句话）
            List<String> improvementSuggestions // 改善建议 2~4 条
    ) {}
}
```

> 如果你坚持用 class + `@Data`，那就必须给 `isNegative` 加 `@JsonProperty("isNegative")`，
> 否则序列化出来的 key 对不上。**用 record 省事，推荐。**

> ℹ️ **7 字段 vs 11 字段**：你库里已有的老数据（如 id=1804）是 **11 字段**
> （多出 `keywords` / `icon` / `label` / `timestamp`），而这里按前端实际读取的 **7 个字段**定义。
> 前端详情弹窗只解析这 7 个 key，**多出来的字段它无视**，所以新老数据都能正常渲染，不影响功能。
> 想让新数据和老数据同构的话，把那 4 个字段也加进 record + 提示词即可（**可选，非必须**）。

### 4.6 Service：`AiService/EmotionDiaryAnalysisService.java`（新建）

```java
package com.lzc.mindaispringboot.AiService;

import cn.hutool.core.text.StrBuilder;
import cn.hutool.json.JSONUtil;
import com.lzc.mindaispringboot.entity.EmotionDiary;
import com.lzc.mindaispringboot.exception.BusionessException;
import com.lzc.mindaispringboot.mappper.EmotionDiaryMapper;
import com.lzc.mindaispringboot.response.ConsultationMessageResponseDTO;
import com.lzc.mindaispringboot.service.ConsultationMessageService;
import com.lzc.mindaispringboot.service.ConsultationSessionService;
import jakarta.annotation.Resource;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.stereotype.Service;

import java.time.LocalDateTime;
import java.util.List;

/**
 * 情绪日记的 AI 分析：分析一条日记，把结构化结果写回 emotion_diary.ai_emotion_analysis。
 */
@Service
public class EmotionDiaryAnalysisService {

    /** 日记内容为空时，回退取该用户最近几个会话的消息作为分析素材 */
    private static final int FALLBACK_SESSIONS = 3;
    /** 送给 AI 的文本上限 */
    private static final int MAX_TEXT_LENGTH = 8000;

    private final ChatClient chatClient;

    @Resource
    private EmotionDiaryMapper emotionDiaryMapper;
    @Resource
    private ConsultationSessionService consultationSessionService;
    @Resource
    private ConsultationMessageService consultationMessageService;

    public EmotionDiaryAnalysisService(@Qualifier("open-ai") ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    /**
     * 分析指定日记并把结果写回数据库。
     * @param force true 表示忽略"近期已分析过"的判断，强制重算
     */
    public StructOutPut.DiaryEmotionAnalysis analyzeAndSave(Long diaryId, boolean force) {
        EmotionDiary diary = emotionDiaryMapper.selectById(diaryId);
        if (diary == null) throw new BusionessException("情绪日记不存在");

        // 24 小时内分析过就不重复烧 token
        if (!force
                && diary.getAiAnalysisUpdatedAt() != null
                && diary.getAiAnalysisUpdatedAt().isAfter(LocalDateTime.now().minusHours(24))) {
            return JSONUtil.toBean(diary.getAiEmotionAnalysis(), StructOutPut.DiaryEmotionAnalysis.class);
        }

        String text = buildText(diary);
        if (text.isBlank()) throw new BusionessException("该日记暂无可分析的内容");

        StructOutPut.DiaryEmotionAnalysis result = chatClient.prompt()
                .system(PromptManage.DIARY_ANALYSIS_PROMPT)
                .user(text)
                .call()                                        // 阻塞式，非流式
                .entity(StructOutPut.DiaryEmotionAnalysis.class);

        // 兜底：AI 偶尔漏字段或缺省，保证前端不会渲染出 undefined
        result = normalize(result);

        diary.setAiEmotionAnalysis(JSONUtil.toJsonStr(result));
        diary.setAiAnalysisUpdatedAt(LocalDateTime.now());
        emotionDiaryMapper.updateById(diary);
        return result;
    }

    /** 组装送给 AI 的文本：优先日记内容，没有就用最近的会话消息 */
    private String buildText(EmotionDiary diary) {
        StrBuilder text = new StrBuilder();

        if (hasText(diary.getDiaryContent()) || hasText(diary.getEmotionTriggers())) {
            text.append("【日记日期】").append(diary.getDiaryDate()).append("\n");
            if (diary.getMoodScore() != null)   text.append("【情绪评分(1-10)】").append(diary.getMoodScore()).append("\n");
            if (diary.getSleepQuality() != null) text.append("【睡眠质量(1-5)】").append(diary.getSleepQuality()).append("\n");
            if (diary.getStressLevel() != null)  text.append("【压力水平(1-5)】").append(diary.getStressLevel()).append("\n");
            if (hasText(diary.getEmotionTriggers()))
                text.append("【情绪触发因素】").append(diary.getEmotionTriggers()).append("\n");
            if (hasText(diary.getDiaryContent()))
                text.append("【日记内容】").append(diary.getDiaryContent()).append("\n");
        } else {
            // 回退：这个用户没写日记内容，用他最近的咨询对话代替
            List<Long> sessionIds = consultationSessionService.listRecentSessionIds(diary.getUserId(), FALLBACK_SESSIONS);
            if (sessionIds.isEmpty()) return "";
            List<ConsultationMessageResponseDTO> messages = consultationMessageService.listBySessionIds(sessionIds);
            if (messages.isEmpty()) return "";
            text.append("【说明】该用户当天没有写日记内容，以下是他最近的咨询对话：\n\n");
            for (ConsultationMessageResponseDTO m : messages) {
                text.append(m.getSenderType() == 1 ? "用户：" : "AI：").append(m.getContent()).append("\n");
            }
        }

        return text.length() > MAX_TEXT_LENGTH
                ? text.subString(text.length() - MAX_TEXT_LENGTH)   // 尾部截断，保留最近内容
                : text.toString();
    }

    /** AI 漏字段时补默认值，避免前端显示 undefined 或进度条异常 */
    private StructOutPut.DiaryEmotionAnalysis normalize(StructOutPut.DiaryEmotionAnalysis r) {
        if (r == null) {
            return new StructOutPut.DiaryEmotionAnalysis("平静", 30, 0, false, "保持当下的节奏就好", "情绪稳定", List.of());
        }
        Integer score = r.emotionScore() == null ? 50 : Math.max(0, Math.min(100, r.emotionScore()));
        Integer risk = r.riskLevel() == null ? 0 : Math.max(0, Math.min(3, r.riskLevel()));
        // 保证 riskLevel 与 isNegative 不矛盾
        Boolean negative = r.isNegative() != null ? r.isNegative() : risk >= 2;
        if (risk >= 2) negative = true;
        if (risk == 0) negative = false;
        return new StructOutPut.DiaryEmotionAnalysis(
                r.primaryEmotion(), score, risk, negative,
                r.suggestion(), r.riskDescription(),
                r.improvementSuggestions() == null ? List.of() : r.improvementSuggestions());
    }

    private boolean hasText(String s) {
        return s != null && !s.isBlank();
    }
}
```

> 这里用到了 `consultationSessionService.listRecentSessionIds` 和
> `consultationMessageService.listBySessionIds` —— 这两个方法在**下面 4.9 节**里定义，
> 如果你暂时不做"会话回退"，可以把那段删掉，直接 `if (!hasText(diaryContent)) return "";`。

### 4.7 接入保存流程：`service/EmotionDiaryService.java`

在 `saveOrUpdate` 的 `return emotionDiary;` **之前**加一段。
关键是 **try-catch 包住**：AI 调用可能超时或失败，**绝不能连累日记保存本身**。

```java
    @Resource
    private EmotionDiaryAnalysisService emotionDiaryAnalysisService;

    // ... saveOrUpdate 原有逻辑不变 ...

        // 保存成功后触发 AI 分析（失败不影响保存结果）
        try {
            emotionDiaryAnalysisService.analyzeAndSave(emotionDiary.getId(), false);
        } catch (Exception e) {
            // 记日志即可，不要往外抛：日记已经存好了，不能因为 AI 挂了就告诉用户"保存失败"
            System.err.println("AI情绪分析失败，diaryId=" + emotionDiary.getId() + "：" + e.getMessage());
        }
        return emotionDiary;
```

> ⚠️ 位置必须在 `insert()` **之后**——自增 id 是 insert 完才回填的，早了 `getId()` 是 null。

**同步 vs 异步的取舍**

| | 同步（上面这份） | 异步 |
|---|---|---|
| 表现 | 保存接口会多等几秒到十几秒 | 保存立刻返回，分析在后台跑 |
| 前端体验 | 详情弹窗打开时结果已就绪 | 刚保存完打开详情可能还没有分析结果 |
| 改动量 | 0（上面这段代码即可） | 启动类加 `@EnableAsync`，方法加 `@Async` |

**建议先同步跑通**，等确认效果对了再改异步。改异步只需两步：
启动类加 `@EnableAsync`，`analyzeAndSave` 方法上加 `@Async`（返回值要改成 `void` 或 `CompletableFuture`）。

### 4.9 用户级情绪画像：基于「全部会话消息」判断每个用户

> 这一节解决的就是你最初提的那个需求：**不看日记，直接从用户所有咨询会话的消息里，判断这个用户整体的情绪状态**。
>
> 管理端要展示的仍然是卡片那 7 项：
> **主要情绪（标签）· 情绪强度（进度条）· 风险等级（标签）· 情绪性质（标签）· 专业建议（单行）· 风险描述（单行）· 改善建议（列表）**
>
> 字段契约与 4.1 完全一致（`primaryEmotion` / `emotionScore` / `riskLevel` / `isNegative` / `suggestion` / `riskDescription` / `improvementSuggestions`），所以**前端渲染逻辑可以直接复用**，不用再写一遍颜色映射。

#### 4.9.1 它和 4.1~4.8（日记维度）的区别

| | 4.1~4.8 日记维度 | 4.9 用户维度 |
|---|---|---|
| 数据来源 | 单条 `emotion_diary` 记录（日记正文+评分+睡眠/压力） | 该用户**全部** `consultation_message`（跨多个会话） |
| 粒度 | 一天一条 | 一个用户一份 |
| 覆盖人群 | 只有**写了日记**的用户 | 只要有**咨询记录**就有（不写日记也能看） |
| 结果存哪 | `emotion_diary.ai_emotion_analysis` | 内存缓存 / 新建表（见 4.9.10） |
| 前端改动 | 0（现有详情弹窗直接渲染） | 需新增一个「用户情绪」列表页 |
| 什么时候算 | 保存日记时触发 | 管理端主动点「分析」时触发 |

两条路不冲突，可以都做：**日记维度保留**（4.1~4.8），**用户维度作为补充**（本节），覆盖那些从不写日记、但经常来咨询的用户。

#### 4.9.3 实现流程（7 步）

```
① 校验权限（@PreAuthorize 拦非管理员）
        ↓
② 取出该用户最近 N 个会话的 sessionId（只查 id，不查内容）
        ↓
③ 一次 SQL 把这些会话的全部消息捞出来（不要 for 循环逐会话查）
        ↓
④ 拼成"用户：xxx / AI：xxx"的纯文本
        ↓
⑤ 超过 12000 字符就【尾部】截断 —— 最近的情绪才代表当前状态
        ↓
⑥ 调 ChatClient，用 .entity(DiaryEmotionAnalysis.class) 拿结构化结果
        ↓
⑦ normalize() 兜底（AI 漏字段 / 值越界 / risk 与 isNegative 矛盾）→ 存缓存 → 组装 VO 返回
```

关键点：**第 ⑦ 步的 `normalize()` 不能省**。AI 偶尔会漏字段或返回 `"2"` 这种字符串，
不兜底的话前端就会出现「进度条没数值」或「显示未知风险等级」。

#### 4.9.4 结构：直接复用 `DiaryEmotionAnalysis`

不用新建结构，4.4 那个 `record` 字段完全够用（7 项一一对应）。
新增的只是**外层的 VO**（多带用户信息和统计数）：

```java

import lombok.Builder;
```

#### 4.9.7 Service：`AiService/UserEmotionAnalysisService.java`（新建）

```java
package com.lzc.mindaispringboot.AiService;

import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.lzc.mindaispringboot.entity.User;
import com.lzc.mindaispringboot.mappper.ConsultationSessionMapper;
import com.lzc.mindaispringboot.mappper.UserMapper;
import com.lzc.mindaispringboot.response.ConsultationMessageResponseDTO;
import com.lzc.mindaispringboot.response.UserEmotionVO;
import com.lzc.mindaispringboot.service.ConsultationMessageService;
import com.lzc.mindaispringboot.service.ConsultationSessionService;
import jakarta.annotation.Resource;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.stereotype.Service;

import java.time.LocalDateTime;
import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

/**
 * 用户级情绪画像：基于该用户【全部咨询会话的消息】做 AI 综合分析。
 * 结果结构与情绪日记卡片完全同构，前端渲染逻辑可直接复用。
 */
@Service
public class UserEmotionAnalysisService {

    /** 最多取最近几个会话（不是全部，防止文本过长烧 token） */
    private static final int MAX_SESSIONS = 5;
    /** 送给 AI 的文本上限，超出从头截掉（保留最近的） */
    private static final int MAX_TEXT_LENGTH = 12000;
    /** 缓存有效小时数 */
    private static final long CACHE_HOURS = 24;

    @Autowired
    @Qualifier("open-ai")
    private ChatClient chatClient;

    @Resource private ConsultationSessionService consultationSessionService;
    @Resource private ConsultationMessageService consultationMessageService;
    @Resource private ConsultationSessionMapper consultationSessionMapper;
    @Resource private UserMapper userMapper;

    /** userId -> 分析结果（重启即失效；要持久化见 4.9.10） */
    private final Map<Long, CacheItem> cache = new ConcurrentHashMap<>();

    private record CacheItem(StructOutPut.DiaryEmotionAnalysis data, LocalDateTime analyzedAt) {}

    /**
     * 分页列表：只读缓存，【绝不触发 AI】。
     * 一页 10 个用户就是 10 次 AI 调用，页面必然超时 —— 这是本节最重要的一个设计约束。
     */
    public Page<UserEmotionVO> page(int pageNum, int pageSize) {
        Page<Long> idPage = new Page<>(pageNum, pageSize);
        Page<Long> userIds = consultationSessionMapper.selectUserIdsOrderByRecent(idPage);

        Page<UserEmotionVO> voPage = new Page<>(pageNum, pageSize);
        voPage.setTotal(userIds.getTotal());

        List<UserEmotionVO> list = new ArrayList<>();
        for (Long userId : userIds.getRecords()) {
            list.add(buildVo(userId, false));
        }
        voPage.setRecords(list);
        return voPage;
    }

    /** 单个用户详情：有缓存用缓存，没有就现场分析一次 */
    public UserEmotionVO detail(Long userId) {
        return buildVo(userId, false);
    }

    /** 强制重算（忽略缓存） */
    public UserEmotionVO refresh(Long userId) {
        return buildVo(userId, true);
    }

    // ==================== 内部实现 ====================

    private UserEmotionVO buildVo(Long userId, boolean force) {
        List<Long> sessionIds = consultationSessionService.listRecentSessionIds(userId, MAX_SESSIONS);
        if (sessionIds.isEmpty()) {
            throw new RuntimeException("该用户暂无咨询会话，无法分析");
        }

        StructOutPut.DiaryEmotionAnalysis data = force ? null : getCached(userId);
        if (data == null) {
            String text = buildText(sessionIds);
            if (text.isEmpty()) {
                throw new RuntimeException("该用户暂无可分析的对话内容");
            }
            data = normalize(chatClient.prompt()
                    .system(PromptManage.USER_EMOTION_ANALYSIS_PROMPT)
                    .user(text)
                    .call()
                    .entity(StructOutPut.DiaryEmotionAnalysis.class));
            cache.put(userId, new CacheItem(data, LocalDateTime.now()));
        }

        UserEmotionVO.UserEmotionVOBuilder b = UserEmotionVO.builder()
                .userId(userId)
                .sessionCount(consultationSessionMapper.countSessions(userId))
                .messageCount(consultationMessageService.countBySessionIds(sessionIds))
                .analyzedAt(cache.get(userId) == null ? null : cache.get(userId).analyzedAt())
                .primaryEmotion(data.primaryEmotion())
                .emotionScore(data.emotionScore())
                .riskLevel(data.riskLevel())
                .isNegative(data.isNegative())
                .suggestion(data.suggestion())
                .riskDescription(data.riskDescription())
                .improvementSuggestions(data.improvementSuggestions());

        User user = userMapper.selectById(userId);
        if (user != null) {
            b.username(user.getUsername()).nickname(user.getNickname());
        }
        return b.build();
    }

    private StructOutPut.DiaryEmotionAnalysis getCached(Long userId) {
        CacheItem item = cache.get(userId);
        if (item == null) return null;
        if (item.analyzedAt().isBefore(LocalDateTime.now().minusHours(CACHE_HOURS))) {
            cache.remove(userId);   // 过期当没有
            return null;
        }
        return item.data();
    }

    /** 把多个会话的消息拼成纯文本 */
    private String buildText(List<Long> sessionIds) {
        List<ConsultationMessageResponseDTO> messages =
                consultationMessageService.listBySessionIds(sessionIds);
        if (messages.isEmpty()) return "";

        StringBuilder sb = new StringBuilder();
        sb.append("【说明】以下是该用户最近 ").append(sessionIds.size()).append(" 个咨询会话的完整对话：\n\n");
        for (ConsultationMessageResponseDTO m : messages) {
            sb.append(m.getSenderType() != null && m.getSenderType() == 1 ? "用户：" : "AI：")
              .append(m.getContent() == null ? "" : m.getContent())
              .append("\n");
        }

        String text = sb.toString();
        // 尾部截断：最近的情绪才代表当前状态，截头部会把最老的内容送给 AI
        return text.length() > MAX_TEXT_LENGTH
                ? text.substring(text.length() - MAX_TEXT_LENGTH)
                : text;
    }

    /** AI 漏字段 / 值越界 / risk 与 isNegative 矛盾时兜底 */
    private StructOutPut.DiaryEmotionAnalysis normalize(StructOutPut.DiaryEmotionAnalysis r) {
        if (r == null) {
            return new StructOutPut.DiaryEmotionAnalysis(
                    "平静", 30, 0, false, "保持当下的节奏就好", "情绪稳定", List.of());
        }
        int score = r.emotionScore() == null ? 50 : Math.max(0, Math.min(100, r.emotionScore()));
        int risk  = r.riskLevel()   == null ? 0  : Math.max(0, Math.min(3,  r.riskLevel()));

        Boolean negative = r.isNegative() != null ? r.isNegative() : risk >= 2;
        if (risk >= 2) negative = true;    // 预警/危机 不可能同时是正面情绪
        if (risk == 0) negative = false;   // 正常 不可能同时是负面情绪

        return new StructOutPut.DiaryEmotionAnalysis(
                r.primaryEmotion(), score, risk, negative,
                r.suggestion(), r.riskDescription(),
                r.improvementSuggestions() == null ? List.of() : r.improvementSuggestions());
    }
}
```

#### 4.9.9 方案 A：想让现有「情绪日志」页面也能看到（前端零改动）

如果你的诉求是**不改前端、就在现在那个情绪日志详情弹窗里看到结果**，

#### 4.9.10 结果存哪：缓存 vs 建表

用户级结果**没有现成的存储列** —— `consultation_session.last_emotion_analysis` 是**会话级**的（一人多行），不能代表整个用户。

| 方案 | 做法 | 适用 |
|---|---|---|
| 内存缓存（上面代码用的） | `ConcurrentHashMap` + 24h TTL | 先跑通；**重启即失效** |
| 新建表 | `user_emotion_profile`（`user_id` 唯一 + `analysis` json + `analyzed_at`） | 正式功能，重启不丢 |
| 挂到 user 表 | 给 `user` 表加一列 `emotion_profile` json | 不想建新表时的折中 |

#### 4.9.13 踩坑清单

| # | 坑 | 说明 |
|---|---|---|
| 1 | **列表接口千万别触发 AI** | 一页 10 个用户 = 10 次调用，页面必超时。列表只读缓存，未分析就显示「未分析」 |
| 2 | **不要循环查库** | `selectBySessionIds` 一次查完多个会话的消息，`for` 里逐会话查会有 N+1 问题 |
| 3 | **必须截断** | 长对话送进去会烧大量 token 甚至超限。且要**尾部**截断，保留最近的 |
| 4 | **AI 调用别放事务里** | 一次几秒到十几秒，放 `@Transactional` 里会长时间占着数据库连接 |
| 5 | **`riskLevel` 要是整数** | AI 返回字符串 `"2"` 时前端对象 key 匹配失败。`normalize()` 已强制转 int |
| 6 | **`emotionScore` 语义** | 你前端是"越高越红"，所以这是"强烈+负面"分，不是"开心程度" |
| 7 | **缓存重启失效** | `ConcurrentHashMap` 在内存里，重启后全部变「未分析」。正式用要建表（4.9.10） |
| 8 | **没会话的用户会报错** | `buildVo` 里先判空抛异常，前端列表页应过滤掉（只查有会话的用户，SQL 已 `GROUP BY user_id`） |
| 9 | **`@PreAuthorize` 需要开关** | `SecurityConfig` 上要有 `@EnableMethodSecurity`，否则注解不生效、任何人都能访问 |
| 10 | **json 列必须合法** | 若用 `user_emotion_profile` 表，`analysis` 是 json 列，写入非法 JSON 会直接报错 |

### 4.11 踩坑清单

| # | 坑 | 说明 |
|---|---|---|
| 1 | **`isNegative` 用 class 会序列化错** | 必须用 `record`，或加 `@JsonProperty("isNegative")`。这是最容易踩的一个 |
| 2 | **`riskLevel` 必须是整数** | 提示词要写"只能是整数 0、1、2、3"。AI 若返回字符串 `"2"`，Jackson 不一定能转 |
| 3 | **`riskLevel` 与 `isNegative` 会矛盾** | 比如 AI 返回 `riskLevel=0` 但 `isNegative=true`，前端会一边绿一边红。`normalize()` 已做强制对齐 |
| 4 | **`emotionScore` 语义** | 你前端是"越高越红"，所以这个分要表示"强烈 + 负面"，不是"开心程度" |
| 5 | **AI 调用别放事务里** | 一次调用几秒到十几秒，放 `@Transactional` 里会长时间占着数据库连接 |
| 6 | **分析失败不能连累保存** | `saveOrUpdate` 里必须 try-catch，日记先存下来 |
| 7 | **调用位置在 `insert()` 之后** | 否则 `getId()` 是 null |
| 8 | **24h 去重** | 同一天反复保存会反复烧 token，用 `ai_analysis_updated_at` 判断 |
| 9 | **批量查询而不是循环查** | 会话回退时用 `listBySessionIds` 一次查完，不要 `for` 里逐会话查 |
| 10 | **`ai_emotion_analysis` 是 text 不是 json** | 存什么都行；但 `consultation_session.last_emotion_analysis` 是 json 列，写入必须合法 |

### 5.2 实现思路

统计类接口最容易写砸的地方是「查一堆数据回 Java 里算」。
正确做法是**让数据库做聚合**（`COUNT` / `AVG` / `GROUP BY`），Java 只负责组装。

本项目里两类手段混用：
- **简单计数**：直接用 MyBatis-Plus 的 `selectCount(new LambdaQueryWrapper<>())`，一行搞定。
- **分组统计 / 趋势**：自定义 `@Select` 写 SQL，返回 `List<Map<String, Object>>`。

## 6. 退出登录

### 6.1 先理解：JWT 退出为什么麻烦

JWT 是**无状态**的——服务端不保存 token，只靠签名校验。这意味着：
**服务端没有任何"开关"能让一个已经发出去的 token 立刻失效。**

所以「退出登录」在 JWT 体系里的标准做法是 **黑名单**：

```
用户点退出 → 服务端把该 token 记进黑名单 → 之后每次请求先查黑名单
          → 命中就返回 401（哪怕签名有效、没过期）
```

### 6.2 代码

#### ① `util/TokenBlacklist.java`（新建）

```java
package com.lzc.mindaispringboot.util;

import com.auth0.jwt.JWT;
import com.auth0.jwt.interfaces.DecodedJWT;

import java.util.Date;
import java.util.Iterator;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

/**
 * token 黑名单（内存版）。
 *
 * 存 token → 过期时间戳。过期时间戳用来做自动清理：
 * 一个 token 过了有效期，本来也就验不过了，没必要永远留在内存里。
 */
public class TokenBlacklist {

    private static final Map<String, Long> BLACKLIST = new ConcurrentHashMap<>();

    /** token 无法解析过期时间时的兜底保留时长：24 小时 */
    private static final long DEFAULT_KEEP_MILLIS = 24 * 60 * 60 * 1000L;

    /** 加入黑名单 */
    public static void add(String token) {
        if (token == null || token.isBlank()) return;
        Long exp = extractExpiration(token);
        BLACKLIST.put(token, exp == null ? System.currentTimeMillis() + DEFAULT_KEEP_MILLIS : exp);
        // 顺手清一次过期的，避免内存无限增长
        cleanExpired();
    }

    /** 是否在黑名单中 */
    public static boolean contains(String token) {
        if (token == null || token.isBlank()) return false;
        Long exp = BLACKLIST.get(token);
        if (exp == null) return false;
        // 已过期的 token 本来也验不过，直接当不在黑名单，省一次判断
        if (exp < System.currentTimeMillis()) {
            BLACKLIST.remove(token);
            return false;
        }
        return true;
    }

    /** 清理已过期的记录 */
    public static void cleanExpired() {
        long now = System.currentTimeMillis();
        Iterator<Map.Entry<String, Long>> it = BLACKLIST.entrySet().iterator();
        while (it.hasNext()) {
            if (it.next().getValue() < now) it.remove();
        }
    }

    /**
     * 解析 token 的过期时间。
     * 这里只 decode 不 verify —— 目的只是拿到过期时间做内存清理，
     * 真正的合法性校验在 JwtTokenUtil.validateToken 里做。
     */
    private static Long extractExpiration(String token) {
        try {
            DecodedJWT jwt = JWT.decode(token);
            Date expiresAt = jwt.getExpiresAt();
            return expiresAt == null ? null : expiresAt.getTime();
        } catch (Exception e) {
            return null;
        }
    }
}
```

### 7.3 ⚠️ 一个需要你先拍板的语义问题

你给的样例是：

```json
{ "primaryEmotion": "失望", "emotionScore": 20, "isNegative": true, "riskLevel": 1 }
```

`emotionScore = 20` 但 `isNegative = true`。而你前端的颜色函数是：

```js
if (score >= 80) return '#f56c6c'   // 红
if (score >= 60) return '#e6a23c'   // 橙
if (score >= 40) return '#909399'   // 灰
return '#67c23a'                    // 绿
```

也就是说 **20 分的进度条是绿色的，但情绪性质标签是红色的**。

这说明：**`emotionScore` 是「情绪强度」，不是「负面程度」**，两个字段是分开看的。

我在下面的提示词里按这个定义写的（`"情绪强度/波动程度"`，与负面与否无关）。
如果你本意是「分数越高越危险」，那就得反过来说一声 —— 提示词改一行的事。

#### 7.5.3 `PsychologicalSupportService.java`：改造 `getEmotionAnalysis`

```java
    public StructOutPut.EmotionAnalysis getEmotionAnalysis(String sessionId, Long userId, boolean isAdmin){
        Long dbsession = extractSessionId(sessionId);
        if (dbsession == null) throw new BusionessException("会话Id格式错误");
        ConsultationSession session = consultationSessionService.getById(dbsession);
        if (session == null) throw new BusionessException("会话不存在");
        if (!isAdmin && !session.getUserId().equals(userId)){
            throw new BusionessException("无权访问该会话");
        }

        // ① 24 小时缓存：有就直接返回
        if (session.getLastEmotionAnalysis() != null
                && session.getLastEmotionUpdatedAt() != null
                && session.getLastEmotionUpdatedAt().isAfter(LocalDateTime.now().minusHours(24))
        ){
            StructOutPut.EmotionAnalysis cached = readCache(session.getLastEmotionAnalysis());
            if (cached != null) return cached;
            // 缓存是旧格式（改造前存的）→ 走到下面重新分析
        }

        // ② 调 AI 分析
        StructOutPut.EmotionAnalysis raw = analyzeSessionEmotion(dbsession);
        // ③ 兜底 + 回填 timestamp
        StructOutPut.EmotionAnalysis analysis = normalize(raw);

        session.setLastEmotionAnalysis(JSONUtil.toJsonStr(analysis));
        session.setLastEmotionUpdatedAt(LocalDateTime.now());
        consultationSessionService.updateById(session);
        return analysis;
    }

    /** 读缓存：解析失败返回 null（旧格式 / 脏数据），让调用方重新分析 */
    private StructOutPut.EmotionAnalysis readCache(String json) {
        try {
            return JSONUtil.toBean(json, StructOutPut.EmotionAnalysis.class);
        } catch (Exception e) {
            return null;
        }
    }

    /** AI 漏字段 / 值越界 / risk 与 isNegative 矛盾时兜底，避免前端显示 undefined */
    private StructOutPut.EmotionAnalysis normalize(StructOutPut.EmotionAnalysis r) {
        String primary = (r == null || r.primaryEmotion() == null) ? "平静" : r.primaryEmotion();

        int score = 50;
        if (r != null && r.emotionScore() != null) {
            score = Math.max(0, Math.min(100, r.emotionScore()));
        }

        int risk = 0;
        if (r != null && r.riskLevel() != null) {
            risk = Math.max(0, Math.min(3, r.riskLevel()));
        }

        Boolean negative = (r != null && r.isNegative() != null) ? r.isNegative() : (risk >= 2);
        if (risk >= 2) negative = true;
        if (risk == 0) negative = false;

        List<String> keywords = (r == null || r.keywords() == null) ? List.of() : r.keywords();
        List<String> improves  = (r == null || r.improvementSuggestions() == null)
                ? List.of() : r.improvementSuggestions();

        return new StructOutPut.EmotionAnalysis(
                primary,
                score,
                negative,
                risk,
                keywords,
                r == null || r.suggestion() == null ? "保持当下的节奏就好" : r.suggestion(),
                r == null || r.icon() == null ? "\uD83D\uDE42" : r.icon(),
                r == null || r.label() == null ? "calm" : r.label(),
                r == null || r.riskDescription() == null ? "情绪稳定" : r.riskDescription(),
                improves,
                System.currentTimeMillis()   // ← timestamp 由后端填
        );
    }
```

### 7.6 缓存兼容：改造后旧数据怎么办

数据库里可能已经存了**旧格式的 JSON**（`{"overallMood":...,"emotions":...}`）。
`JSONUtil.toBean` 解析成新 record 时，新字段全为 `null`——前端就会收到一个全空的卡片。

所以 7.5.3 里加了 `readCache()`：解析异常就返回 `null`，自动重新分析。
但为了让旧格式**当场失效**（不用等 24 小时），建议改完先清一次缓存：

```sql
UPDATE consultation_session
   SET last_emotion_analysis = NULL,
       last_emotion_updated_at = NULL;
```

> ⚠️ `consultation_session.last_emotion_analysis` 是 **`json`** 列，写入必须是合法 JSON，
> 否则 MySQL 直接报错（跟 `emotion_diary.ai_emotion_analysis` 的 `text` 列不一样）。

另外提醒：`JSONUtil.toBean` 对 **record** 的支持并不稳妥（Hutool 靠反射/Unsafe 实例化）。
若遇到反序列化报奇怪的错，换成 Jackson 更保险：

```java
    @Resource
    private ObjectMapper objectMapper;   // 或 new ObjectMapper()

    private StructOutPut.EmotionAnalysis readCache(String json) {
        try {
            return objectMapper.readValue(json, StructOutPut.EmotionAnalysis.class);
        } catch (Exception e) {
            return null;
        }
    }
```

写入同理可以把 `JSONUtil.toJsonStr(analysis)` 换成 `objectMapper.writeValueAsString(analysis)`。

### 7.8 踩坑清单

| # | 坑 | 说明 |
|---|---|---|
| 1 | **`isNegative` 必须用 record** | 用 class + `@Data`，Jackson 可能序列化成 `"negative"`，前端读到 `undefined` |
| 2 | **`riskLevel` 必须是整数** | 前端 `riskTagMap[riskLevel]` 的 key 是数字；AI 若返回 `"1"`，对象匹配失败 → 显示「未知风险等级」 |
| 3 | **`emotionScore` 不要返回小数** | AI 偶尔返回 `20.0` 或 `"20"`，Jackson 转 Integer 可能报错。`normalize()` 已强转 int |
| 4 | **旧缓存要清** | 不改数据的话，`last_emotion_analysis` 里的旧格式 JSON 会被当成有效缓存返回空卡片 |
| 5 | **`json` 列必须合法** | `last_emotion_analysis` 是 json 类型，写入非法 JSON 直接报错 |
| 6 | **`timestamp` 不要交给 AI** | AI 不知道当前时间，会编一个。必须由后端 `System.currentTimeMillis()` 填 |
| 7 | **`icon` 别限制成单字节字符** | emoji 是代理对（surrogate pair），MySQL 需 `utf8mb4`——你的库已经是，没问题 |
| 8 | **`Result` 加了字段会不会影响别的接口** | 不会，是纯新增 key，前端不读就无影响 |
| 9 | **24h 缓存会让调试困惑** | 改完 prompt 后想立刻看效果，先执行 7.6 那条 SQL 清缓存 |
| 10 | **`JSONUtil.toBean` 解析 record 不稳** | 报错就换 `ObjectMapper`（7.6 给了写法） |

### 7.9 用户端「情绪花园」对接要点（按你的 `Consultation.vue` 逐行核对）

#### 7.9.1 实际用到的字段只有 7 个

左侧「情绪花园」渲染的是 `currentEmotion`，逐行抄下来：

| 模板位置 | 字段 | 用法 |
|---|---|---|
| 情绪圆 | `primaryEmotion` | 直接显示文字（**不做颜色映射**，不像管理端那 10 个值） |
| 情绪圆 | `emotionScore` | 直接显示数字 |
| 圆变黄条件 / 「今天感觉」文案 | `isNegative` | `isNegative ? '需要关注' : '很不错'`，`.negative` 类切到 `--warn-bg` |
| 强度点 + 等级文案 | `emotionScore` / `riskLevel` | `getIntensityClass(score)`：≥61→3 点，≥31→2 点，否则 1 点<br>`getEiskText(riskLevel)`：0正常 1关注 2预警 3危机 |
| 给你的小建议 | `suggestion` | 单行文本 |
| 治愈小行动 | `improvementSuggestions` | `v-for` 列表，**模板里直接 `.length`** |
| ⚠️ 风险提示 | `riskDescription` | 仅当 `isNegative && riskLevel > 1` 才显示 |

**结论**：`keywords` / `icon` / `label` / `timestamp` 在用户端**一个都没用到**。
保留它们没坏处（管理端可能要用），但不是这个页面必需的。

`getEiskText` 的 0/1/2/3 映射与第 7 章定的 `riskLevel` 完全一致 ✅。

#### 7.9.2 调用时机：会打两次

```js
onmessage: (event) => {
  if (event.event === 'done') { isAiTyping=false; ctrl.abort(); loadSessionEmotion(...); return }
  ...
}
onclose: () => { loadSessionEmotion(...) }
```

后端确实会发 `event: done`（`PsychologicalChatController` 里 `concatWith` 追加的），
且**在 `doOnComplete` 保存 AI 消息之后**才发——所以分析时能读到最后一轮回复，时序是安全的 ✅。

但 `ctrl.abort()` 关闭连接后 `onclose` 又会触发一次 → **同一个 emotion 接口被并发打两次**。
两次都Miss缓存 = **两次 AI 调用，双倍 token**。

改法（前端）：

```js
let emotionRequested = false          // ← 新增标志位

const loadSessionEmotion = async (sessionId) => {
  if (emotionRequested) return        // ← 同一次流只拉一次
  emotionRequested = true
  const id = sessionId.toString().startsWith('session_') ? sessionId : `session_${sessionId}`
  const res = await getSeeionEmotion(id)
  currentEmotion.value = res
}

// 发新一轮前重置
const sendMessage = () => { emotionRequested = false; ... }
```

这是后端的问题。现有 `getEmotionAnalysis` 的缓存判据只看了时间：

```java
if (lastEmotionAnalysis != null && lastEmotionUpdatedAt.isAfter(now.minusHours(24))) return cached;
```

用户早上聊完拿到结果，**下午继续聊了 20 条，情绪花园还是早上那份** —— 这跟他"实时反馈"的体感是冲突的。

建议改成「**时间 + 消息条数**」双判据（后端改，约 5 行）：

```java
    // 参与分析的消息条数，缓存时一起记下来
    long currentCount = consultationMessageService.countBySession(dbsession);

    if (session.getLastEmotionAnalysis() != null
            && session.getLastEmotionUpdatedAt() != null
            && session.getLastEmotionUpdatedAt().isAfter(LocalDateTime.now().minusHours(24))
            && session.getLastEmotionMsgCount() != null
            && session.getLastEmotionMsgCount() == currentCount   // ← 消息没变才用缓存
    ){
        StructOutPut.EmotionAnalysis cached = readCache(session.getLastEmotionAnalysis());
        if (cached != null) return cached;
    }

    StructOutPut.EmotionAnalysis analysis = normalize(analyzeSessionEmotion(dbsession));
    session.setLastEmotionAnalysis(JSONUtil.toJsonStr(analysis));
    session.setLastEmotionUpdatedAt(LocalDateTime.now());
    session.setLastEmotionMsgCount((int) currentCount);          // ← 记下来
    consultationSessionService.updateById(session);
```

需要在 `consultation_session` 表加一列：

```sql
ALTER TABLE consultation_session
  ADD COLUMN last_emotion_msg_count int DEFAULT 0 COMMENT '上次情绪分析时的消息条数'
  AFTER last_emotion_updated_at;
```

实体 `ConsultationSession` 同步加字段（MyBatis-Plus 默认开启驼峰转下划线，`lastEmotionMsgCount` → `last_emotion_msg_count`）：

```java
    // 上次情绪分析时的消息条数（用于判断是否需要重新分析）
    @TableField("last_emotion_msg_count")
    private Integer lastEmotionMsgCount;
```

> 这样既保留了「24 小时内不重复烧 token」的保护，又能保证**每多一轮对话就刷新一次**情绪花园。

#### 8.2.1 路径对不上（先确认前端到底打的是哪条）

| 字段 | 来源 | 算法 |
|---|---|---|

| `nickname` | `user.nickname` | 按 `user_id` 关联（可以为 null） |
| `diaryContentPreview` | `diary_content` | 取前 50 字，超长补 `…` |
| `contentLength` | `diary_content` | `content == null ? 0 : content.length()` |
| `hasAiEmotionAnalysis` | `ai_emotion_analysis` | `StringUtils.hasText(...)` |
| `aiAnalysisStatus` | 同上 | 有值 → `COMPLETED`，无值 → `PENDING` |

#### 8.2.3 排序：现在是乱的（其实是主键升序）

#### 8.2.4 外层 `success` / `message`

```java
public Page<EmotionDiaryAdminVO> adminPage(EmotionDiaryAdminPageQuery query) {
    LambdaQueryWrapper<EmotionDiary> qw = new LambdaQueryWrapper<>();

    if (query.getStartDate() != null) qw.ge(EmotionDiary::getDiaryDate, query.getStartDate());

    // 新增：按创建时间倒序（最新的在前），同秒用 id 兜底
    qw.orderByDesc(EmotionDiary::getCreatedAt).orderByDesc(EmotionDiary::getId);

    Page<EmotionDiary> page = emotionDiaryMapper.selectPage(

            .filter(Objects::nonNull)
```

| 坑 | 后果 | 怎么避 |

## 附录 A：建议顺手修的 3 处技术债

这些不影响上面 6 个接口的功能，但**越早修越好**，尤其是 A.1。

### A.1 `JwtTokenUtil` 不读 yaml 配置（高优先）

**问题**：`application.yml` 配了 `header: Authorization` + `token-prefix: "Bearer "`，
但 `extractTokenFromRequest` 写死读 `token` 头，这两个配置**完全是摆设**。
前端如果按标准写法发 `Authorization: Bearer xxx`，会**全部 401**。

**改法**（`util/JwtTokenUtil.java`）：

```java
    public static String extractTokenFromRequest(HttpServletRequest request){
        if (request == null) return null;
        JwtConfig jwtConfig = getJwtConfig();

        // 优先读配置的请求头（Authorization）
        String header = request.getHeader(jwtConfig.getHeader());
        if (StringUtils.hasText(header)) {
            // 去掉前缀 "Bearer "
            String prefix = jwtConfig.getTokenPrefix();
            if (prefix != null && !prefix.isEmpty() && header.startsWith(prefix)) {
                header = header.substring(prefix.length()).trim();
            }
            if (StringUtils.hasText(header)) return header;
        }
        // 兼容旧的 token 头（老前端还在用，保留一段时间）
        String legacy = request.getHeader("token");
        return StringUtils.hasText(legacy) ? legacy : null;
    }
```

这样两种写法都能用，**前端不用改**，等你确认统一后可以把兼容分支删掉。
（需要先确认 `JwtConfig` 里有 `getHeader()` / `getTokenPrefix()` 这两个 getter，没有就补上。）

### A.2 `streamChat` 缺少会话归属校验（高优先）

**问题**：`PsychologicalChatController` 里 `/sessions/{id}/messages` 和 `/sessions/{id}` 都做了
`checkOwnership()`，唯独 `/stream` 没做——**任何人拿到别人的 sessionId 都能往里发消息**。

**改法**：在 `streamChat` 方法里，`Long userId = Token_Aspect.getUserId();` 之后加两行：

```java
        Long dbSessionId = extractDbSessionId(consultaionStreamDTO.getSessionId());
        checkOwnership(dbSessionId);
```

| 报错 | 原因 |
