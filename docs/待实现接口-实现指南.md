### 0.4 通用约定（写代码前先记住这 5 条）

**① 统一响应体 `Result<T>`**

```json
{ "code": "200", "msg": "操作成功", "data": { } }
```
失败抛 `BusionessException("提示语")`，由 `GlobarExceptionHandler` 兜住。

**② 鉴权：请求头 `token`，裸 JWT（不带 Bearer）**

当前 `JwtTokenUtil.extractTokenFromRequest` 写死读 `token` 头；`application.yml` 里的
`header: Authorization` + `token-prefix: "Bearer "` **目前是摆设**（改法见 **4.2**）。

**③ 取当前登录用户**

```java
@GetToken                          // 标在 Controller 方法上，切面解析 token
Long userId = Token_Aspect.getUserId();
```

**④ 管理员判定**

```java
@PreAuthorize("hasRole('2')")           // 管理端专用接口，不满足直接 403
boolean isAdmin = AuthUtil.isAdmin();   // 同一接口两种行为时用（如 /sessions）
```

**⑤ 展示字段一律走 VO，不要塞进实体**

给实体加 `@TableField(exist = false)` 字段会连累用户端接口，还可能被 MyBatis-Plus 拿去拼 SQL。
统一写法：新建 `xxxVO` + 静态工厂 `from(实体, ...)`（参考已完成的 `EmotionDiaryAdminVO`）。

### 1.3 DTO：双端页码 + 删掉拼错的 `pargeNum`

**问题**：`/sessions` 是同一个接口，但**两端发的页码参数名不一样**，而 DTO 里的字段还拼错了：

```java
// 现状：common/Dto/SessionPageQuery.java
private Long pargeNum = 1L;        // ← 拼错（应为 pageNum），而且两端都不叫这个名字
```

| 端 | 前端代码 | 实际发出 | 现状能接住吗 |
|---|---|---|---|
| 用户端 | `getSessionList({ pageNum: 1, pageSize: 10 })`（`Consultation.vue`） | `?pageNum=1` | ❌ 字段叫 `pargeNum` |
| 管理端 | `pagination = { currentPage: 1, pageSize: 10 }`（`Consultations.vue`） | `?currentPage=1` | ❌ 字段叫 `pargeNum` |

**后果：两端都绑不上，页码永远用默认值 1 → 点第 2 页拿到的还是第 1 页。**
（`pageSize` 两端名字都对得上，所以"每页 10 条"看起来正常，最容易忽略。）

**修复目标**：删掉 `pargeNum`，**同时接住两个名字**：

```java
package com.lzc.mindaispringboot.common.Dto;

import lombok.Data;

@Data
public class SessionPageQuery {
    /** 管理端传的页码（Consultations.vue） */
    private Long currentPage;
    /** 用户端传的页码（Consultation.vue） */
    private Long pageNum;
    /** 每页条数：两端都叫 pageSize */
    private Long pageSize = 10L;
    /** 按用户过滤；仅管理员生效，普通用户强制看自己的 */
    private Long userId;
    /** 标题关键字模糊搜索（可选） */
    private String keyword;

    /** 两端兼容取页码：currentPage 优先 → pageNum → 兜底 1 */
    public Long resolvePage() {
        if (currentPage != null) return currentPage;
        if (pageNum != null) return pageNum;
        return 1L;
    }
}
```

> ⚠️ **不要**用「保留 `pargeNum` 做兼容」的写法 —— 已确认**两端都不传这个名字**，留着只会误导。
>
> ⚠️ 改完这个 DTO，Service 里原来 `query.getPageNum()` 那行会立刻编译不过，
> 要一起换成 `query.resolvePage()`（见 1.4）。**1.3 和 1.4 必须同时改。**

### 1.4 Service：`service/ConsultationSessionService.java`

要点：**不要在 for 里逐条查消息/用户**（N+1），改成"先批量查一次，再在内存里分组拼装"。
另外，把下面的 `getPageNum()` 那类取值统一换成 **1.3 的 `query.resolvePage()`**。

```java
    /** 分页查询会话列表（带用户昵称 + 消息数 / 最后消息预览） */
    public Page<SessionAdminVO> pageSessions(SessionPageQuery query) {
        // ① 只查会话本身（分页 + 条件 + 排序）
        LambdaQueryWrapper<ConsultationSession> qw = new LambdaQueryWrapper<>();
        if (query.getUserId() != null) {
            qw.eq(ConsultationSession::getUserId, query.getUserId());
        }
        if (StrUtil.isNotBlank(query.getKeyword())) {
            qw.like(ConsultationSession::getSessionTitle, query.getKeyword());
        }
        qw.orderByDesc(ConsultationSession::getStartedAt);   // 最近的在最前

        Page<ConsultationSession> page = consultationSessionMapper.selectPage(
                new Page<>(query.resolvePage(), query.getPageSize()), qw);   // ← 双端页码兼容

        List<ConsultationSession> records = page.getRecords();
        Page<SessionAdminVO> result =
                new Page<>(page.getCurrent(), page.getSize(), page.getTotal());
        if (records.isEmpty()) {
            result.setRecords(List.of());
            return result;
        }

        List<Long> sessionIds = records.stream().map(ConsultationSession::getId).toList();

        // ② 一次查出这批会话的全部消息，按 sessionId 分组（避免 N+1）
        List<ConsultationMessage> allMessages = consultionMessageMapper.selectList(
                new LambdaQueryWrapper<ConsultationMessage>()
                        .in(ConsultationMessage::getSessionId, sessionIds)
                        .orderByAsc(ConsultationMessage::getCreatedAt));   // 升序，最后一条是末位
        Map<Long, List<ConsultationMessage>> msgGroup = allMessages.stream()
                .collect(Collectors.groupingBy(ConsultationMessage::getSessionId));

        // ③ 一次查出这批用户
        List<Long> userIds = records.stream().map(ConsultationSession::getUserId).distinct().toList();
        Map<Long, User> userMap = userMapper.selectBatchIds(userIds).stream()
                .collect(Collectors.toMap(User::getId, u -> u));

        // ④ 内存拼装
        List<SessionAdminVO> voList = new ArrayList<>();
        for (ConsultationSession s : records) {
            List<ConsultationMessage> msgs = msgGroup.getOrDefault(s.getId(), List.of());
            ConsultationMessage last = msgs.isEmpty() ? null : msgs.get(msgs.size() - 1);
            User u = userMap.get(s.getUserId());
            voList.add(SessionAdminVO.builder()
                    .id(s.getId())
                    .userId(s.getUserId())
                    .userNickname(u == null ? null : u.getDisplayName())   // 昵称优先，没昵称退用户名
                    .sessionTitle(s.getSessionTitle())
                    .lastMessageContent(last == null ? null : SessionAdminVO.preview(last.getContent()))
                    .messageCount((long) msgs.size())
                    .lastMessageTime(last == null ? null : last.getCreatedAt())
                    .startedAt(s.getStartedAt())
                    .build());
        }
        result.setRecords(voList);
        return result;
    }
```

### 2.1 前端要什么：顶层 4 个 key 的嵌套结构

`Dashboard.vue` 是从 **4 个顶层 key** 取值的，且都是**嵌套对象 / 数组**。
下面是它逐个字段的读取路径 —— **这一列就是契约，一个都不能改**：

| 前端实际读取路径 | 类型 | 说明 |
|---|---|---|
| `systemOverview.totalUsers` | 数字 | 总用户数 |
| `systemOverview.activeUsers` | 数字 | 近 7 日活跃用户（去重） |
| `systemOverview.totalDiaries` | 数字 | 日记总数 |
| `systemOverview.todayNewDiaries` | 数字 | 今日新增日记 |
| `systemOverview.totalSessions` | 数字 | 会话总数 |
| `systemOverview.todayNewSessions` | 数字 | 今日新增会话 |
| `systemOverview.avgMoodScore` | 数字 | 平均情绪分（一位小数） |
| `emotionTrend[].{date, avgMoodScore, recordCount}` | 数组（≤7） | 情绪趋势折线图 |
| `consultationStats.totalSessions` | 数字 | 总会话数（与上面同值，前端两处都读了） |
| `consultationStats.avgDurationMinutes` | 数字 | 平均时长（见 2.7，当前恒 0） |
| `consultationStats.dailyTrend[].{date, sessionCount, userCount}` | 数组（≤7） | 咨询活动柱状图 |
| `userActivity[].{date, activeUsers, newUsers, diaryUsers, consultationUsers}` | 数组（≤7） | 用户活跃度折线图 |

**三条趋势数组长度必须恒为 7**（哪天没数据就补 `0` / `null`），否则折线图 X 轴会跳天。

> ⚠️ **最常见的写错方式**：把它写成扁平结构（`userCount` / `moodTrend[].avgMood` 这种）。
> 前端不做字段兜底（直接 `ov.totalUsers` 取值），**字段名或层级错一个，4 张概览卡就是空白、3 个图表就是空曲线** ——
> 而且**接口本身会返回 200，不报任何错**，只会"页面没数据"，很难查。

import com.lzc.mindaispringboot.mappper.ConsultationSessionMapper;

import jakarta.annotation.Resource;
import org.springframework.stereotype.Service;

import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

@Service
public class DataAnalyticsService {

    /** 趋势窗口天数（含今天） */
    private static final int DAYS = 7;
    private static final DateTimeFormatter FMT = DateTimeFormatter.ofPattern("yyyy-MM-dd");

    @Resource private UserMapper userMapper;
    @Resource private ConsultationSessionMapper consultationSessionMapper;
    @Resource private EmotionDiaryMapper emotionDiaryMapper;

    public DataAnalyticsVO overview() {

        // ① 日期骨架：连续 7 天，保证前端 X 轴不断档

        Map<String, Map<String, Object>> newUserDaily = toMap(userMapper.selectNewUserDaily7d());
        Map<String, Map<String, Object>> activeDaily  = toMap(userMapper.selectActiveUserDaily7d());

        // ③ 按骨架组装三条趋势（缺的天补 0 / null）
        List<DataAnalyticsVO.EmotionTrendPoint> emotionTrend = new ArrayList<>();
        List<DataAnalyticsVO.DailySessionPoint> dailyTrend = new ArrayList<>();
        List<DataAnalyticsVO.UserActivityPoint> userActivity = new ArrayList<>();

        for (String day : days) {
            Map<String, Object> d = diaryDaily.get(day);
            Map<String, Object> s = sessionDaily.get(day);
            Map<String, Object> n = newUserDaily.get(day);
            Map<String, Object> a = activeDaily.get(day);

                    .avgMoodScore(toDouble(d == null ? null : d.get("avgMoodScore")))
                    .recordCount(toLong(d == null ? null : d.get("recordCount")))
                    .build());

            dailyTrend.add(DataAnalyticsVO.DailySessionPoint.builder()
                    .date(day)
                    .sessionCount(toLong(s == null ? null : s.get("sessionCount")))
                    .userCount(toLong(s == null ? null : s.get("userCount")))
                    .build());

            userActivity.add(DataAnalyticsVO.UserActivityPoint.builder()
                    .date(day)
                    .activeUsers(toLong(a == null ? null : a.get("activeUsers")))
                    .newUsers(toLong(n == null ? null : n.get("newUsers")))
                    .diaryUsers(toLong(d == null ? null : d.get("diaryUsers")))
                    .consultationUsers(toLong(s == null ? null : s.get("userCount")))  // 与会话用户数同源
                    .build());
        }

        // ④ 概览卡片
        String todayKey = today.format(FMT);
        long totalSessions = consultationSessionMapper.selectCount(new LambdaQueryWrapper<>());
        DataAnalyticsVO.SystemOverview overview = DataAnalyticsVO.SystemOverview.builder()
                .totalUsers(userMapper.selectCount(new LambdaQueryWrapper<>()))

    /** List<Map> → Map<date, Map> */
    private Map<String, Map<String, Object>> toMap(List<Map<String, Object>> rows) {
        Map<String, Map<String, Object>> map = new HashMap<>();
        for (Map<String, Object> row : rows) {
            Object date = row.get("date");
            if (date != null) map.put(String.valueOf(date), row);
        }
        return map;
    }

    private Long fromMap(Map<String, Map<String, Object>> daily, String day, String key) {
        Map<String, Object> row = daily.get(day);
        return row == null ? 0L : toLong(row.get(key));
    }

    /** 统一按 Number 处理：COUNT(*) 可能被驱动映射成 Long / BigInteger，强转会 ClassCastException */
    private static Long toLong(Object o) {
        return o == null ? 0L : ((Number) o).longValue();
    }

    private static Double toDouble(Object o) {
        return o == null ? null : ((Number) o).doubleValue();
    }

## 3. 退出登录

### 3.0 目标

| 项 | 内容 |
|---|---|

| 验收 | 退出后用旧 token 再请求，返回 `A0230`（token 失效） |

### 3.1 先理解：JWT 退出为什么麻烦

JWT 是**无状态**的——服务端不保存 token，只靠签名校验。这意味着：
**服务端没有任何"开关"能让一个已经发出去的 token 立刻失效。**

所以「退出登录」在 JWT 体系里的标准做法是 **黑名单**：

```
用户点退出 → 服务端把该 token 记进黑名单 → 之后每次请求先查黑名单
          → 命中就返回 401（哪怕签名有效、没过期）
```

### 3.2 代码

#### ① `util/TokenBlacklist.java`（新建）

```java
package com.lzc.mindaispringboot.util;

import com.auth0.jwt.JWT;
import com.auth0.jwt.interfaces.DecodedJWT;

import java.util.Date;
import java.util.Iterator;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

/**
 * token 黑名单（内存版）。
 *
 * 存 token → 过期时间戳。过期时间戳用来做自动清理：
 * 一个 token 过了有效期，本来也就验不过了，没必要永远留在内存里。
 */
public class TokenBlacklist {

    private static final Map<String, Long> BLACKLIST = new ConcurrentHashMap<>();

    /** token 无法解析过期时间时的兜底保留时长：24 小时 */
    private static final long DEFAULT_KEEP_MILLIS = 24 * 60 * 60 * 1000L;

    /** 加入黑名单 */
    public static void add(String token) {
        if (token == null || token.isBlank()) return;
        Long exp = extractExpiration(token);
        BLACKLIST.put(token, exp == null ? System.currentTimeMillis() + DEFAULT_KEEP_MILLIS : exp);
        // 顺手清一次过期的，避免内存无限增长
        cleanExpired();
    }

    /** 是否在黑名单中 */
    public static boolean contains(String token) {
        if (token == null || token.isBlank()) return false;
        Long exp = BLACKLIST.get(token);
        if (exp == null) return false;
        // 已过期的 token 本来也验不过，直接当不在黑名单，省一次判断
        if (exp < System.currentTimeMillis()) {
            BLACKLIST.remove(token);
            return false;
        }
        return true;
    }

    /** 清理已过期的记录 */
    public static void cleanExpired() {
        long now = System.currentTimeMillis();
        Iterator<Map.Entry<String, Long>> it = BLACKLIST.entrySet().iterator();
        while (it.hasNext()) {
            if (it.next().getValue() < now) it.remove();
        }
    }

    /**
     * 解析 token 的过期时间。
     * 这里只 decode 不 verify —— 目的只是拿到过期时间做内存清理，
     * 真正的合法性校验在 JwtTokenUtil.validateToken 里做。
     */
    private static Long extractExpiration(String token) {
        try {
            DecodedJWT jwt = JWT.decode(token);
            Date expiresAt = jwt.getExpiresAt();
            return expiresAt == null ? null : expiresAt.getTime();
        } catch (Exception e) {
            return null;
        }
    }
}
```

### 4.2 `JwtTokenUtil` 不读 yaml 配置（高优先）

**问题**：`application.yml` 配了 `header: Authorization` + `token-prefix: "Bearer "`，
但 `extractTokenFromRequest` **写死读 `token` 头**，这两个配置完全是摆设。
前端如果按标准写法发 `Authorization: Bearer xxx`，会**全部 401**。

**修复目标**：两种写法都能用（配置的头优先，旧的 `token` 头留作兼容），前端不用改。

**改法**（`util/JwtTokenUtil.java`）：

```java
    public static String extractTokenFromRequest(HttpServletRequest request){
        if (request == null) return null;
        JwtConfig jwtConfig = getJwtConfig();

        // 优先读配置的请求头（Authorization）
        String header = request.getHeader(jwtConfig.getHeader());
        if (StringUtils.hasText(header)) {
            // 去掉前缀 "Bearer "
            String prefix = jwtConfig.getTokenPrefix();
            if (prefix != null && !prefix.isEmpty() && header.startsWith(prefix)) {
                header = header.substring(prefix.length()).trim();
            }
            if (StringUtils.hasText(header)) return header;
        }
        // 兼容旧的 token 头（老前端还在用，保留一段时间）
        String legacy = request.getHeader("token");
        return StringUtils.hasText(legacy) ? legacy : null;
    }
```

> 需要先确认 `JwtConfig` 里有 `getHeader()` / `getTokenPrefix()` 这两个 getter，没有就补上。
> 等确认前端统一后，可以把兼容分支删掉。

**验收**：改成 `Authorization: Bearer xxx` 后能正常鉴权；同时旧的 `token: xxx` 仍然可用。
