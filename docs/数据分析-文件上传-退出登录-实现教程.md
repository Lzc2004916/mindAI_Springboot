# 第 0 步：基础设施（一次性改完）

## 0.1 修改 `resources/application.yml`

**操作**：在 `spring:` 节点下加 `servlet.multipart`，文件末尾加 `app:` 节点。

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 20MB        # 单文件上限
      max-request-size: 20MB     # 整个请求上限

app:
  upload:
    dir: D:/mindai/uploads       # Windows 本地；Linux 部署写 /data/mindai/uploads
```

**原理**
- `spring.servlet.multipart.*` 是 Spring Boot 内置的文件上传限制，不配的话超限会抛 `MaxUploadSizeExceededException`。
- `app.upload.dir` 是**自定义**配置项，后面 `FileService` 用 `@Value("${app.upload.dir:./uploads}")` 读它。`:./uploads` 是默认值（配置缺失时用）。

## 0.2 新增 `config/WebMvcConfig.java`

**操作**：新建文件（注意包名 `config`）。

```java
package com.lzc.mindaispringboot.config;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.ResourceHandlerRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

/**
 * Web MVC 配置：把上传目录映射成静态资源。
 * 访问 /files/xxx 时，实际读取 ${app.upload.dir}/xxx 下的文件。
 */
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {
    @Value("${app.upload.dir:./uploads}")
    private String uploadDir;

    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        // /files/xxx  -->  磁盘 uploadDir/xxx
        registry.addResourceHandler("/files/**")
                .addResourceLocations("file:" + (uploadDir.endsWith("/") ? uploadDir : uploadDir + "/"));
    }
}
```

**原理**
- 上传的文件存在**磁盘目录**里，数据库只存文件名。要让浏览器能通过 URL 访问，必须做一个「URL → 磁盘目录」的映射。
- `addResourceHandler("/files/**")` 表示任何以 `/files/` 开头的请求都由静态资源处理器接管；`addResourceLocations("file:...")` 指定实际磁盘路径。
- `file:` 前缀是告诉 Spring「这是文件系统路径」（不加会被当成 classpath 路径）。
- 末尾补 `/`：Spring 要求 location 以 `/` 结尾，否则拼接文件名会出错。

## 0.3 修改 `config/SecurityConfig.java`

**操作**：只改一处——`PUBLIC_MATCHERS` 里加 `/files/**`。

## 0.4 新增 `service/TokenBlacklistService.java`

**操作**：新建文件。

```java
package com.lzc.mindaispringboot.service;

import org.springframework.stereotype.Service;

import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

/**
 * token 黑名单（退出登录用）。内存版：重启后黑名单清空，
 * 因 token 本身有 24h 过期时间，重启丢失的影响只是"已退出"的 token 最多再活到自然过期。
 */
@Service
public class TokenBlacklistService {
    private final Map<String, Long> blacklist = new ConcurrentHashMap<>();

    /** 拉黑 token 到指定时间戳（毫秒） */
    public void add(String token, long expireAtMillis) {
        cleanUp();
        blacklist.put(token, expireAtMillis);
    }

    /** 该 token 是否已被拉黑且尚未自然过期 */
    public boolean isBlocked(String token) {
        Long expireAt = blacklist.get(token);
        if (expireAt == null) return false;
        if (expireAt < System.currentTimeMillis()) {
            blacklist.remove(token);
            return false;
        }
        return true;
    }

    /** 顺带清理已自然过期的条目，防止 Map 无限增长 */
    private void cleanUp() {
        long now = System.currentTimeMillis();
        blacklist.entrySet().removeIf(e -> e.getValue() < now);
    }
}
```

**原理（为什么需要黑名单）**
- JWT 是**无状态**的：token 一旦签发，在过期前服务端无法"撤回"。用户点退出，前端删掉本地 token 就行了，但**那个 token 若被人拿到，仍能用**。
- 黑名单就是服务端记一笔"这些 token 已作废"，请求时先查一下，命中就拒绝。
- `ConcurrentHashMap`：多线程并发访问安全（Web 环境必须）。
- **value 存过期时间戳**，而不是无脑存下去：一是过期后自动失效，二是 `cleanUp()` 能定期清理，避免内存无限增长。
- 内存版的代价：服务重启后黑名单丢失，已登出的 token 会"复活"到自然过期。要严格化就换 Redis（接口不变）。

## 0.5 修改 `util/JwtAuthticationFilter.java`

**操作**：加 1 个 import + 1 个字段 + 1 段黑名单校验（在"无 token 校验"之后、"验证 token"之前）。

**改动 1**：加 import
```java

```

**改动 2**：加字段
```java

    public UserService userService;

    public TokenBlacklistService tokenBlacklistService;   // 新增
```

**改动 3**：`doFilterInternal` 里插入黑名单校验（注意后面注释编号顺延）
```java
        // 1. 无 token，拒绝
        if (!StringUtils.hasText(token)) {
            clearSecurityContext();
            ResponseUtil.writeResponse(response, ResultCode.ACCESS_UNAUTHORIZED);
            return;
        }

        // 2. 【新增】已退出登录（黑名单）的 token 直接拒绝
        if (tokenBlacklistService.isBlocked(token)) {
            clearSecurityContext();
            ResponseUtil.writeResponse(response, ResultCode.TOKEN_BLOCKED);
            return;
        }

        // 3. 验证 token
        JwtTokenUtil.TokenVerificationResult TokenResult = JwtTokenUtil.validateToken(token);
        // 4. claims 残缺，拒绝
        ...
```

**原理**
- 校验顺序很重要：**先判黑名单，再验签**。已登出的 token 直接拦掉，省一次验签开销。
- 返回 `ResultCode.TOKEN_BLOCKED`（而不是 TOKEN_INVALID），前端可据此区分"token 过期"和"已登出"。
- 过滤器本身是 `@Bean`（在 `SecurityConfig` 里 `new` 出来的），Spring 会注入 `@Resource` 字段，所以能拿到 `TokenBlacklistService`。

## 2.3 新增 `service/FileService.java`

```java
package com.lzc.mindaispringboot.service;

import com.lzc.mindaispringboot.entity.SysFileInfo;
import com.lzc.mindaispringboot.exception.BusionessException;
import com.lzc.mindaispringboot.mappper.SysFileInfoMapper;
import jakarta.annotation.Resource;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;
import org.springframework.web.multipart.MultipartFile;

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.nio.file.StandardCopyOption;
import java.time.LocalDateTime;
import java.util.List;
import java.util.UUID;

@Service
public class FileService {
    @Resource
    private SysFileInfoMapper fileMapper;

    @Value("${app.upload.dir:./uploads}")
    private String uploadDir;

    public SysFileInfo upload(MultipartFile file, String businessType, String businessId, Long uploadUserId) {
        if (file == null || file.isEmpty()) {
            throw new BusionessException("上传文件不能为空");
        }
        String originalName = file.getOriginalFilename() == null ? "unknown" : file.getOriginalFilename();
        String ext = "";
        int dot = originalName.lastIndexOf('.');
        if (dot >= 0) ext = originalName.substring(dot + 1).toLowerCase();
        String fileType = resolveFileType(ext);
        // 磁盘文件名用 UUID，防止重名/路径穿越
        String storedName = UUID.randomUUID().toString().replace("-", "") + (ext.isEmpty() ? "" : "." + ext);
        try {
            Path dir = Paths.get(uploadDir).toAbsolutePath();
            Files.createDirectories(dir);
            Files.copy(file.getInputStream(), dir.resolve(storedName), StandardCopyOption.REPLACE_EXISTING);
        } catch (IOException e) {
            throw new BusionessException("文件保存失败");
        }
        SysFileInfo info = SysFileInfo.builder()
                .originalName(originalName)
                .filePath(storedName)
                .fileSize(file.getSize())
                .fileType(fileType)
                .businessType(businessType)
                .businessId(businessId)
                .uploadUserId(uploadUserId)
                .isTemp(0)
                .status(1)
                .createTime(LocalDateTime.now())
                .build();
        fileMapper.insert(info);
        return info;
    }

    /** 按扩展名归类文件类型 */
    private String resolveFileType(String ext) {
        if (List.of("jpg", "jpeg", "png", "gif", "bmp", "webp").contains(ext)) return "IMG";
        if (ext.equals("pdf")) return "PDF";
        if (List.of("txt", "md").contains(ext)) return "TXT";
        if (List.of("doc", "docx").contains(ext)) return "DOC";
        if (List.of("xls", "xlsx", "csv").contains(ext)) return "XLS";
        return "OTHER";
    }
}
```

**原理**
- **为什么用 UUID 当文件名**：① 防重名（两个用户都传 `1.jpg` 不会互相覆盖）；② **防路径穿越攻击**（若直接用用户传的文件名如 `../../etc/passwd`，会写到目录外；用 UUID 就彻底规避）。
- `Files.createDirectories(dir)`：目录不存在就自动创建（含多级）。
- `StandardCopyOption.REPLACE_EXISTING`：同名时覆盖（UUID 理论上不会重名，加上更保险）。
- **原始名和存储名分开存**：`original_name` 给用户看，`file_path` 是磁盘真实名。
- 文件先落盘、再写库：如果写库失败，最多留个孤儿文件，不会出现"库里有记录但文件不存在"。

```java
    @PostMapping("/upload")
    public Result<Map<String, Object>> upload(@RequestParam("file") MultipartFile file,
                                              @RequestParam(value = "businessType", required = false) String businessType,
                                              @RequestParam(value = "businessId", required = false) String businessId) {
        Long userId = Token_Aspect.getUserId();
        SysFileInfo info = fileService.upload(file, businessType, businessId, userId);
        Map<String, Object> data = new LinkedHashMap<>();
        data.put("id", info.getId());
        data.put("originalName", info.getOriginalName());
        data.put("fileSize", info.getFileSize());
        data.put("fileType", info.getFileType());
        data.put("url", "/files/" + info.getFilePath());
        return Result.success(data);
    }
}
```

**E-1 实现流程**：① `Token_Aspect` 取上传人 userId → ② `file` 非空校验 → ③ 按扩展名归类 `file_type` → ④ 生成 UUID 存储名，`Files.copy` 写入上传目录 → ⑤ 元数据落库 `sys_file_info` → ⑥ 返回 `url=/files/<存储名>`（该地址已在 `SecurityConfig` 放行、由 `WebMvcConfig` 映射到磁盘）。

**前端怎么传**（关键，容易踩坑）：

```js
const fd = new FormData();
fd.append('file', fileInput.files[0]);
// 可选：fd.append('businessType', 'ARTICLE_COVER');
await axios.post('/api/file/upload', fd, {
  headers: {
    'token': localStorage.getItem('token'),
    // ⚠️ 不要手动设 Content-Type，让它自动带 boundary
  }
});
```

**原理**：`multipart/form-data` 请求必须由浏览器自动生成 `Content-Type: multipart/form-data; boundary=xxx`。**手动设置 `Content-Type: application/json` 会导致后端报 `Current request is not a multipart request`**，这是最常见的上传报错。

# 第 3 步：用户退出登录

## 3.1 修改 `controller/UserController.java`

**操作**：加 2 个 import、1 个字段、1 个方法，并**删掉误 import**（`org.antlr.runtime.Token`）。

**完整文件（可直接替换）**：

```java
package com.lzc.mindaispringboot.controller;

import com.auth0.jwt.interfaces.DecodedJWT;
import com.lzc.mindaispringboot.Aop.GetToken;
import com.lzc.mindaispringboot.Aop.Token_Aspect;
import com.lzc.mindaispringboot.common.Dto.UserLoginCommandDTO;
import com.lzc.mindaispringboot.common.Dto.UserRegisterCommandDTO;
import com.lzc.mindaispringboot.common.Result;
import com.lzc.mindaispringboot.response.UserLoginResponseDTO;
import com.lzc.mindaispringboot.service.TokenBlacklistService;
import com.lzc.mindaispringboot.service.UserService;
import com.lzc.mindaispringboot.util.JwtTokenUtil;
import jakarta.annotation.Resource;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.validation.Valid;
import org.springframework.util.StringUtils;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/user")
public class UserController {
    //登录
    @Resource
    private UserService userService;
    @Resource
    private TokenBlacklistService tokenBlacklistService;

    @PostMapping("/login")
    public Result<UserLoginResponseDTO> login(@Valid @RequestBody UserLoginCommandDTO userLoginCommandDTO) {
        UserLoginResponseDTO result = userService.login(userLoginCommandDTO);
        return Result.success(result);
    }

    //添加账号
    @PostMapping("/add")
    public Result<UserLoginResponseDTO.UserDetailResponseDTO> register(@Valid @RequestBody UserRegisterCommandDTO userRegisterCommandDTO){
        UserLoginResponseDTO.UserDetailResponseDTO result = userService.register(userRegisterCommandDTO);
        return Result.success(result);
    }

    //获取账号信息
    @GetToken
    @GetMapping("/current")
    public Result<UserLoginResponseDTO.UserDetailResponseDTO> getCurrentUser(){
        Long userId = Token_Aspect.getUserId();
        UserLoginResponseDTO.UserDetailResponseDTO result = userService.getUserById(userId);
        return Result.success(result);
    }

    //退出登录：把当前 token 拉黑到其自然过期时间
    @GetToken
    @PostMapping("/logout")
    public Result<Void> logout(HttpServletRequest request) {
        String token = JwtTokenUtil.extractTokenFromRequest(request);
        if (StringUtils.hasText(token)) {
            DecodedJWT jwt = JwtTokenUtil.verifyToken(token);
            long remainMillis = jwt.getExpiresAt().getTime() - System.currentTimeMillis();
            tokenBlacklistService.add(token, System.currentTimeMillis() + Math.max(remainMillis, 0));
        }
        return Result.success();
    }
}
```

**F-1 实现流程**：① `@GetToken` AOP 先验 token（无效直接异常）→ ② 取出 token，`verifyToken` 拿到 `expiresAt`，算出**剩余有效期** → ③ `add(token, 当前时间 + 剩余毫秒)` 拉黑到自然过期 → ④ 之后该 token 的任何请求会被过滤器第 2 步拦截（`TOKEN_BLOCKED`，401）→ ⑤ 前端同时清本地 token。

**原理**
- **为什么算"剩余有效期"而不是存很久**：token 本身最长活 24h，黑名单记到它的过期时间就够了，过了这个点 token 自己就失效了，黑名单条目可清理。
- `Math.max(remainMillis, 0)`：兜底，万一 token 刚好过期（算出负数），也不会把过期时间设成过去之外的值。
- `@GetToken` + 手动从 request 取 token：因为这里**需要 token 原文**（要拉黑它），而 `Token_Aspect.getUserId()` 只给了 userId。

**前端配合**：退出成功后清掉本地 token：

```js
await axios.post('/api/user/logout', {}, { headers: { token: localStorage.getItem('token') } });
localStorage.removeItem('token');
```
