## 2. ⚠️ 动过一半 / 需要修正（8 项·重点）

### O-01 · 精简 `Result`
- **现状**：`message` 字段已经没了，但 **`success` 还在**。
- **证据**：`common/Result.java` 字段为 `code / msg / data / success`。
- **差什么**：文档要求 `success` 也去掉（可由 `code` 推出），并把 `msg` 的语义定成唯一文案字段。注意去掉后前端若有 `res.success` 判断会受影响（⚠️ 前端要同步）。

### O-03 · 处理死码 `A0232 / A0233 / A0300`
- **现状**：`A0232 TOKEN_EXPIRED` 已真正用起来（`JwtAuthticationFilter.java:51`）；`A0300 AUTHORIZED_ERROR` 已被 `AccessDeniedException` 处理器使用（`GlobarExceptionHandler.java:47`）。
- **差什么**：**`A0233 TOKEN_BLOCKED` 仍是死码**——它只在 `util/ResponseUtil.java:21` 的 `switch` 里被"匹配"，但全项目**没有任何地方会产生这个状态**（没有黑名单机制），所以永远走不到。

### O-08 · `refresh-expiration` 要么用、要么删
- **现状**：已加 `POST /api/user/renew`（`UserController.java:58`）＋ `UserService.renewToken()`。
- **🐞 但这里有 bug**：`service/UserService.java:126` 把 **`userId.intValue()` 当成了 `tokenVersion`** 传给 `generateToken`：
  ```java
  return JwtTokenUtil.generateToken(user.getId(), user.getUsername(), user.getUserType(), userId.intValue());
  //                                                                                        ^^^^^^^^^^^^^^^^^ 应为 user.getTokenVersion()
  ```
  后果：新 token 里的 `tokenVersion` claim 与库里 `user.token_version` 对不上 → `JwtAuthticationFilter.java:68` 的版本比对直接判不过 → **续出来的 token 立刻失效**（除非 userId 恰好等于 tokenVersion，比如 id=1 且 token_version=1）。位置：`UserService.renewToken`。

### O-14 · 去掉切面里重复的鉴权
- **现状**：切面**已不再重新解析 token**（这部分随 O-11 一起完成了）✅。
- **差什么**：`@GetToken` + `ThreadLocal` 仍然存在（O-13 未做），切面里还留着 `userId == null → throw BusionessException("未登录")`（`Token_Aspect.java:31`）——这是过滤器之外的第二道兜底，严格说属于重复鉴权。另外 `Token_Aspect.getCurrentRequest()`（`:48`）**没有任何调用方**，是死方法。

### O-25 · 前端用返回的新 token 做「无感续期」（⚠️ 前端改动）
- **现状**：后端 `changePassword` 已返回新 token（`UserService.java:120`），后端侧齐了。
- **差什么**：前端尚未用返回的新 token 覆盖本地（属于前端仓库 `Mental_health_programme` 的改动，不在本次后端范围）。

### O-26 · 重命名：类名 / 方法名 / 路由
- **已完成**：入参类 `common/Dto/ChangesPassword_Username.java` → `Dto/ChangePasswordRequest.java` ✅；路由见 O-30 ✅。
- **差什么**：**Controller 的方法名还叫 `Changes`**（`UserController.java:43`），类名 `BusionessException` 的拼写也仍在（见 O-04）。

### O-46 · `SessionPageQuery` 收敛成一个页码字段
- **现状**：加了 `resolvePage()` / `resolvePageSize()` 兼容层（`Dto/SessionPageQuery.java:22`、`:29`），行为上没问题。
- **差什么**：`currentPage` 与 `pageNum` **两个字段并存**，没有真正收敛成一个（前端两套命名都还能传）。

### O-47 · `saveOrUpdate` + `enqueue` 的一致性（P0）
- **现状**：`EmotionDiaryService.saveOrUpdate`（`:33`）仍是「写库 → `try { enqueue } catch { log.warn }`」，**没有 `@Transactional`**。
- **判定**：这**恰好等价于文档里的「方案 B」（日记必须存上，入队失败只记日志）**。
  - 如果你的目标就是 B → 本项可视作「已按 B 落地，无需改动」，只需补一句注释说明这是有意选择；
  - 如果你要的是 A（强一致：入不了队就整体回滚）→ 还差 `@Transactional` + 去掉 `try/catch`。
