# 第一部分：咨询记录模块

## 1.1 目标接口清单

| 编号 | 方法 | 路径 | 鉴权 | 作用 |
|---|---|---|---|---|
| G-1 | GET | `/api/psychological-chat/sessions` | 登录 | 查询会话列表（管理员全量 / 用户只看自己） |
| G-2 | GET | `/api/psychological-chat/sessions/{sessionId}/messages` | 登录 | 查某会话全部消息 |
| G-4 | DELETE | `/api/psychological-chat/sessions/{sessionId}` | 登录 | 删会话（连消息一起删） |
| G-3 | GET | `/api/psychological-chat/session/{sessionId}/emotion` | 登录 | 会话情绪分析（24h 缓存） |

> 注意路径细节：消息/删除用复数 `sessions`，情绪分析用单数 `session`（对齐全项目既有风格，别改）。

## 1.2 数据模型（项目原有 2 张表）

```
consultation_session (会话)
  id, user_id, session_title, started_at,
  last_emotion_analysis, last_emotion_updated_at   ← 情绪分析缓存字段

consultation_message (消息)
  id, session_id, sender_type(1用户/2AI), message_type(1文本),
  content, emotion_tag, ai_model, created_at
```

**关联关系**：`consultation_message.session_id → consultation_session.id`，一个会话多条消息（一对多）。

> ⚠️ 实体现状：`ConsultationSession`、`ConsultationMessage` 只有 `@Data @Builder`，**没有无参构造**。MyBatis 结果映射需要无参构造，如果运行时报 `Cannot instantiate`/映射异常，给这两个实体补上 `@NoArgsConstructor @AllArgsConstructor` 即可（本次新增的实体都要带齐）。

## 1.3 第一步：无需新增 DTO（跳过）

会话列表接口**不分页**，直接用一个 `@RequestParam(value = "userId", required = false)` 接收"管理员按用户过滤"的可选参数即可，**不需要** `SessionPageQuery` 这个 DTO。

> 📌 说明：原设计稿是「分页查会话」（返回 `Page` + `SessionPageQuery`）。现改为「列表查会话」：一次返回该用户的全部会话（按 `started_at` 倒序）。个人会话量通常在几十条内，列表足够；以后会话量大了再改回分页即可。

## 1.4 第二步：改造 `ConsultationMessageService`

**文件**：`service/ConsultationMessageService.java`

追加两个方法，并删除一行误 import。**完整文件如下**：

```java
package com.lzc.mindaispringboot.service;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.lzc.mindaispringboot.entity.ConsultationMessage;
import com.lzc.mindaispringboot.mappper.ConsultionMessageMapper;
import com.lzc.mindaispringboot.response.ConsultationMessageResponseDTO;
import jakarta.annotation.Resource;
import org.springframework.stereotype.Service;

import java.time.LocalDateTime;
import java.util.List;
import java.util.stream.Collectors;

@Service
public class ConsultationMessageService {
    @Resource
    public ConsultionMessageMapper consultionMessageMapper;

    //保存的是用户的消息
    public ConsultationMessage saveUserMessage(Long sessionId, String content, String emotion_tag) {
        ConsultationMessage userMessage = ConsultationMessage.builder()
                .sessionId(sessionId)
                .senderType(1)
                .messageType(1)
                .content(content)
                .emotionTag(emotion_tag)
                .createdAt(LocalDateTime.now())
                .build();
        consultionMessageMapper.insert(userMessage);
        return userMessage;
    }

    //保存Ai消息
    public ConsultationMessage saveAiMessage(Long sessionId, String content, String ai_model) {
        ConsultationMessage AiMessage = ConsultationMessage.builder()
                .sessionId(sessionId)
                .senderType(2)
                .messageType(1)
                .content(content)
                .aiModel(ai_model)
                .createdAt(LocalDateTime.now())
                .build();
        consultionMessageMapper.insert(AiMessage);
        return AiMessage;
    }

    public Integer getMessageCount(Long sessionId) {
        LambdaQueryWrapper<ConsultationMessage> queryWrapper = new LambdaQueryWrapper<>();
        queryWrapper.eq(ConsultationMessage::getSessionId, sessionId);
        return consultionMessageMapper.selectCount(queryWrapper).intValue();
    }

    /// 获取会话中最新的消息数据
    public ConsultationMessageResponseDTO getLastMessageBySessionId(Long sessionId) {
        LambdaQueryWrapper<ConsultationMessage> queryWrapper = new LambdaQueryWrapper<>();
        queryWrapper.eq(ConsultationMessage::getSessionId, sessionId)
                .orderByDesc(ConsultationMessage::getCreatedAt)
                .last("limit 1");
        ConsultationMessage lastMessage = consultionMessageMapper.selectOne(queryWrapper);
        return lastMessage != null ? convertToResponseDTO(lastMessage) : null;
    }

    // ============ 新增 1：按时间升序返回会话全部消息 ============
    public List<ConsultationMessageResponseDTO> listBySession(Long sessionId) {
        LambdaQueryWrapper<ConsultationMessage> qw = new LambdaQueryWrapper<>();
        qw.eq(ConsultationMessage::getSessionId, sessionId)
                .orderByAsc(ConsultationMessage::getCreatedAt);
        return consultionMessageMapper.selectList(qw).stream()
                .map(this::convertToResponseDTO)
                .collect(Collectors.toList());
    }

    // ============ 新增 2：删除会话全部消息 ============
    public void deleteBySessionId(Long sessionId) {
        LambdaQueryWrapper<ConsultationMessage> qw = new LambdaQueryWrapper<>();
        qw.eq(ConsultationMessage::getSessionId, sessionId);
        consultionMessageMapper.delete(qw);
    }

    public ConsultationMessageResponseDTO convertToResponseDTO(ConsultationMessage message) {
        if (message == null) return null;
        ConsultationMessageResponseDTO dto = ConsultationMessageResponseDTO.builder()
                .id(message.getId())
                .sessionId(message.getSessionId())
                .senderType(message.getSenderType())
                .senderTypeDesc(message.getSenderTypeDesc())
                .messageType(message.getMessageType())
                .messageTypeDesc(message.getMessageTypeDesc())
                .content(message.getContent())
                .emotionTag(message.getEmotionTag())
                .aiModel(message.getAiModel())
                .createdAt(message.getCreatedAt())
                .build();
        dto.calculateContentLength();
        return dto;
    }
}
```

**改了什么**
1. 删除 `import ch.qos.logback.core.encoder.LayoutWrappingEncoder;`（原本误 import，且未使用）。
2. 新增 `listBySession`：按 `created_at` **升序**查全部消息（聊天要按时间正序渲染）。
3. 新增 `deleteBySessionId`：`delete` + 等值 wrapper 清空该会话消息。

**原理**
- `orderByAsc(createdAt)` 而不用 `orderByDesc`：聊天记录是"从上往下读"，必须正序。
- `.map(this::convertToResponseDTO)`：把实体逐条转成 DTO（补上 `senderTypeDesc`、`contentLength` 这些数据库里没有的展示字段）。
- 删除用 `delete(wrapper)` 而不是 `deleteById`：按"会话 id"批量删（一条 SQL 删全部消息）。

## 1.5 第三步：改造 `ConsultationSessionService`

**文件**：`service/ConsultationSessionService.java`

**完整文件如下**（含修复标题 bug）：

```java
package com.lzc.mindaispringboot.service;

import cn.hutool.core.date.DateUtil;
import cn.hutool.core.util.StrUtil;
import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.lzc.mindaispringboot.common.Dto.ConsultationSessionCreateDto;
import com.lzc.mindaispringboot.entity.ConsultationSession;
import com.lzc.mindaispringboot.entity.User;
import com.lzc.mindaispringboot.exception.BusionessException;
import com.lzc.mindaispringboot.mappper.ConsultationSessionMapper;
import com.lzc.mindaispringboot.mappper.UserMapper;
import jakarta.annotation.Resource;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

import java.time.LocalDateTime;
import java.util.List;

@Service
public class ConsultationSessionService {
    @Autowired
    private UserMapper userMapper;
    @Autowired
    private ConsultationSessionMapper consultationSessionMapper;
    @Resource
    private ConsultationMessageService consultationMessageService;

    public ConsultationSession createSession(Long userId, ConsultationSessionCreateDto SessionCreateDto) {
        //验证用户是否存在
        User user = userMapper.selectById(userId);
        if (user != null) {
            //创建会话记录
            ConsultationSession session = ConsultationSession.builder()
                    .userId(userId)
                    .sessionTitle(SessionCreateDto.getSessionTitle())
                    .startedAt(LocalDateTime.now())
                    .build();
            // ✅ 修复：标题为空时才用默认标题（原逻辑写反，会把用户自定义标题覆盖掉）
            if (StrUtil.isBlank(SessionCreateDto.getSessionTitle())) {
                session.setSessionTitle("宁渡AI助手 - " + DateUtil.format(LocalDateTime.now(), "MM-dd-yyyy HH:mm:ss"));
            }
            consultationSessionMapper.insert(session);
            return session;
        }
        throw new BusionessException("用户不存在");
    }

    // ============ 新增 1：查询会话列表 ============
    /** userId 为空查全部（管理端），否则只查该用户（用户端），按开始时间倒序 */
    public List<ConsultationSession> listSessions(Long userId) {
        LambdaQueryWrapper<ConsultationSession> qw = new LambdaQueryWrapper<>();
        if (userId != null) qw.eq(ConsultationSession::getUserId, userId);
        qw.orderByDesc(ConsultationSession::getStartedAt);
        return consultationSessionMapper.selectList(qw);
    }

    // ============ 新增 2：按主键取单条 ============
    public ConsultationSession getById(Long id) {
        return consultationSessionMapper.selectById(id);
    }

    // ============ 新增 3：更新会话（情绪分析结果写回用） ============
    public void updateById(ConsultationSession session) {
        consultationSessionMapper.updateById(session);
    }

    // ============ 新增 4：删会话（含消息） ============
    /** 删除会话及其全部消息（调用方需先做归属校验） */
    public void deleteSession(Long id) {
        if (consultationSessionMapper.selectById(id) == null) {
            throw new BusionessException("会话不存在");
        }
        consultationMessageService.deleteBySessionId(id);  // 先删消息
        consultationSessionMapper.deleteById(id);          // 再删会话
    }
}
```

**改了什么 & 为什么**

| 改动 | 原理 |
|---|---|
| 修 `if (!StrUtil.isBlank(...))` → `if (StrUtil.isBlank(...))` | 原逻辑"有标题反而覆盖成默认标题"，条件写反了 |
| `createSession` 末尾 `return null` → `throw new BusionessException("用户不存在")` | 返回 null 会让上层 `session.getId()` 空指针；抛异常由全局处理器统一转错误响应 |
| 新增 `listSessions` | `userId != null` 才拼 `WHERE user_id=?`，实现"管理员看全量、用户看自己"；按 `started_at` 倒序（最近会话在最前）。用 `selectList` 一次取回，**不分页** |
| 新增 `getById` | 给归属校验用（判断会话属不属于当前用户） |
| 新增 `updateById` | 给情绪分析结果写回用（见 1.7 的 `getEmotionAnalysis`） |
| 新增 `deleteSession` | **先删消息再删会话**：即使数据库没建级联外键，也能保证不残留孤儿消息 |
| 注入 `ConsultationMessageService` | `deleteSession` 里要调它删消息 |

## 1.6 第四步：补 `StructOutPut` 与 `PromptManage`

### 1.6.1 `AiService/StructOutPut.java`（追加一个 record）

```java
package com.lzc.mindaispringboot.AiService;

import java.util.List;

public class StructOutPut {
    public record StreamChatSession(
            String sessionId,
            Long userHash,
            String initialMessage,
            Long startTime,
            Long expiryTime,
            Integer messageCount,
            String status
    ) {
    }

    /** 会话情绪分析结构化结果（AI 输出） */
    public record EmotionAnalysis(
            String overallMood,        // 总体情绪：平静/焦虑/低落/积极/愤怒/混乱
            List<String> emotions,     // 出现过的情绪（2-5 个）
            Double positiveRatio,      // 积极情绪占比 0~1
            String summary,            // 100 字内总结
            List<String> suggestions   // 2-4 条温和建议
    ) {
    }
}
```

**原理**：`record` 是 Java 16+ 的不可变数据类，Spring AI 的 `.entity(Class)` 结构化输出靠它做 **JSON → 对象** 的映射。字段名必须和 AI 输出的 JSON key 一一对应。放在 `StructOutPut`（结构化输出）这个类里，语义集中。

## 1.7 第五步：`PsychologicalSupportService` 加情绪分析

**文件**：`AiService/PsychologicalSupportService.java`

在原文件基础上，**追加 import** 并**追加两个方法**（其余不动）：

```java
// ===== 追加 import =====
import cn.hutool.json.JSONUtil;
import com.lzc.mindaispringboot.exception.BusionessException;
import java.time.LocalDateTime;
import java.util.List;
```

```java
    // ==================== 新增：会话情绪分析 ====================

    /**
     * 获取会话情绪分析（24 小时缓存）。
     * 缓存未过期 → 直接读 consultation_session.last_emotion_analysis；
     * 过期/为空 → 拉取会话消息让 AI 做结构化分析，结果落库后返回。
     */
    public StructOutPut.EmotionAnalysis getEmotionAnalysis(String sessionId, Long userId, boolean isAdmin) {
        Long dbSession = extractSessionId(sessionId);
        if (dbSession == null) throw new BusionessException("会话ID格式错误");
        ConsultationSession session = consultationSessionService.getById(dbSession);
        if (session == null) throw new BusionessException("会话不存在");
        // 归属校验：非管理员只能看自己的
        if (!isAdmin && !session.getUserId().equals(userId)) {
            throw new BusionessException("无权访问该会话");
        }
        // 24 小时内的分析结果直接复用，避免重复消耗 AI tokens
        if (session.getLastEmotionAnalysis() != null && session.getLastEmotionUpdatedAt() != null
                && session.getLastEmotionUpdatedAt().isAfter(LocalDateTime.now().minusHours(24))) {
            return JSONUtil.toBean(session.getLastEmotionAnalysis(), StructOutPut.EmotionAnalysis.class);
        }
        // 缓存失效 → 重新分析并写回
        StructOutPut.EmotionAnalysis analysis = analyzeSessionEmotion(dbSession);
        session.setLastEmotionAnalysis(JSONUtil.toJsonStr(analysis));
        session.setLastEmotionUpdatedAt(LocalDateTime.now());
        consultationSessionService.updateById(session);
        return analysis;
    }

    /** 拉取会话消息 → 拼接对话 → AI 结构化情绪分析 */
    private StructOutPut.EmotionAnalysis analyzeSessionEmotion(Long dbSessionId) {
        List<ConsultationMessageResponseDTO> messages = consultationMessageService.listBySession(dbSessionId);
        if (messages.isEmpty()) throw new BusionessException("该会话暂无消息，无法进行情绪分析");
        StrBuilder dialogue = new StrBuilder();
        for (ConsultationMessageResponseDTO m : messages) {
            dialogue.append(m.getSenderType() == 1 ? "用户：" : "AI：").append(m.getContent()).append("\n");
        }
        // 超长截断（保留最近 8000 字符），避免超过模型上下文
        String text = dialogue.length() > 8000
                ? dialogue.substring(dialogue.length() - 8000)
                : dialogue.toString();
        // .system() 覆盖 ChatClient 默认系统提示词，.entity() 走结构化输出
        return chatClient.prompt()
                .system(PromptManage.EMOTION_ANALYSIS_PROMPT)
                .user(text)
                .call()
                .entity(StructOutPut.EmotionAnalysis.class);
    }
```

> 说明：这里调用的 `consultationSessionService.updateById(...)` 已在 **1.5** 里定义好，无需重复添加。

**原理（这段是整个模块最"值钱"的部分）**
1. **24 小时缓存**：情绪分析要调一次 AI（花钱、慢）。结果存进 `consultation_session.last_emotion_analysis`，只要 24h 内就秒回，不重复消耗 token。
2. **缓存三条件**：`last_emotion_analysis` 非空 **且** `last_emotion_updated_at` 非空 **且** 该时间在 24h 内——任意一条不满足才重新分析。
3. **`.system()` 覆盖默认提示词**：`ChatClientConfig` 里默认挂了心理疏导提示词，这里显式 `.system()` 换成"情绪分析"提示词，避免两套指令打架。
4. **`.entity(Class)`**：让 Spring AI 直接把 AI 返回的 JSON 反序列化成 `EmotionAnalysis` 对象，不用自己 parse。
5. **8000 字符截尾**：长对话会超出模型上下文窗口，截取"最近的对话"（`substring(length-8000)`）既省 token 又保留最新状态。

```java
    // ==================== 新增接口 ====================

    /** 查询会话列表：管理员=全部（可传 userId 过滤）；用户=只看自己的 */
    @GetToken
    @GetMapping("/sessions")
    public Result<List<ConsultationSession>> listSessions(
            @RequestParam(value = "userId", required = false) Long userId) {
        Long currentUserId = Token_Aspect.getUserId();
        Long filterUserId = AuthUtil.isAdmin() ? userId : currentUserId;
        return Result.success(consultationSessionService.listSessions(filterUserId));
    }

    /** 会话消息列表（用户只能看自己的会话） */
    @GetToken
    @GetMapping("/sessions/{sessionId}/messages")
    public Result<List<ConsultationMessageResponseDTO>> listMessages(@PathVariable String sessionId) {
        checkOwnership(sessionId);
        return Result.success(consultationMessageService.listBySession(extractDbSessionId(sessionId)));
    }

    /** 删除会话（级联删除消息；用户只能删自己的） */
    @GetToken
    @DeleteMapping("/sessions/{sessionId}")
    public Result<Void> deleteSession(@PathVariable String sessionId) {
        checkOwnership(sessionId);
        consultationSessionService.deleteSession(extractDbSessionId(sessionId));
        return Result.success();
    }

    /** 会话情绪分析（24小时缓存；用户只能分析自己的会话） */
    @GetToken
    @GetMapping("/session/{sessionId}/emotion")
    public Result<StructOutPut.EmotionAnalysis> sessionEmotion(@PathVariable String sessionId) {
        Long userId = Token_Aspect.getUserId();
        return Result.success(psychologicalSupportService
                .getEmotionAnalysis(sessionId, userId, AuthUtil.isAdmin()));
    }

    // ==================== 私有辅助 ====================

    /** 解析路径里的 sessionId（兼容 session_1 / 1 两种格式） */
    private Long extractDbSessionId(String sessionId) {
        try {
            String s = sessionId.startsWith("session_")
                    ? sessionId.substring("session_".length()) : sessionId;
            return Long.parseLong(s);
        } catch (Exception e) {
            throw new BusionessException("会话ID格式错误");
        }
    }

    /** 非管理员只能操作自己的会话 */
    private void checkOwnership(String sessionId) {
        if (AuthUtil.isAdmin()) return;
        Long dbSession = extractDbSessionId(sessionId);
        ConsultationSession session = consultationSessionService.getById(dbSession);
        if (session == null) throw new BusionessException("会话不存在");
        if (!session.getUserId().equals(Token_Aspect.getUserId())) {
            throw new BusionessException("无权操作该会话");
        }
    }
```

## 1.9 四个接口的实现原理（逐条）

| 接口 | 关键动作 | 为什么这么写 |
|---|---|---|
| **G-1** 会话列表 | `AuthUtil.isAdmin() ? userId : currentUserId` | 管理员可传 `userId` 过滤、不传看全部；普通用户**强制**只看自己（前端传了也不算数，防越权）。返回 `List`，不分页 |
| **G-2** 消息列表 | `extractDbSessionId` → `checkOwnership` → `listBySession` | 先解析主键、再验归属，最后查消息并转 DTO |
| **G-4** 删会话 | `checkOwnership` → `deleteSession` | 先删消息再删会话，避免孤儿数据 |
| **G-3** 情绪分析 | 归属校验 → 缓存判断 → 调 AI → 写回 | 见 1.7 原理（缓存 + 截断 + 结构化输出） |

**为什么把归属校验写成 `checkOwnership` 私有方法**：`G-2`、`G-4` 都要校验，抽出来避免复制粘贴；而且它内置了"管理员跳过校验"的分支。

**为什么 `sessionId` 兼容 `session_1` 和 `1` 两种**：`/session/start` 返回的是 `"session_" + id`，前端可能原样带回来，也可能只带数字，两种都接受体验更好。

## 1.10 咨询模块踩坑清单

| # | 坑 | 现象 | 解决 |
|---|---|---|---|
| 1 | 实体缺无参构造 | 查会话列表时 `Cannot instantiate ConsultationSession` | `ConsultationSession` / `ConsultationMessage` 补 `@NoArgsConstructor @AllArgsConstructor` |

| 5 | 忘记 `updateById` | 分析结果不落库，每次都调 AI | `ConsultationSessionService` 补 `updateById` |

```java
@Mapper
public interface EmotionDiaryMapper extends BaseMapper<EmotionDiary> {

    /** 近 N 天每日情绪均分与日记数（趋势图用） */
```

## 2.6 第四步：Service `EmotionDiaryService`

**文件**：`service/EmotionDiaryService.java`

```java
package com.lzc.mindaispringboot.service;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.lzc.mindaispringboot.common.Dto.EmotionDiaryAdminPageQuery;
import com.lzc.mindaispringboot.common.Dto.EmotionDiarySaveDTO;
import com.lzc.mindaispringboot.entity.EmotionDiary;
import com.lzc.mindaispringboot.exception.BusionessException;
import com.lzc.mindaispringboot.mappper.EmotionDiaryMapper;
import jakarta.annotation.Resource;
import org.springframework.stereotype.Service;

import java.time.LocalDateTime;

@Service
public class EmotionDiaryService {
    @Resource
    private EmotionDiaryMapper diaryMapper;

    /** 用户端：按 用户+日期 幂等创建或更新（表有 user_date_unique 唯一键） */
    public EmotionDiary saveOrUpdate(Long userId, EmotionDiarySaveDTO dto) {
        LambdaQueryWrapper<EmotionDiary> qw = new LambdaQueryWrapper<>();
        qw.eq(EmotionDiary::getUserId, userId).eq(EmotionDiary::getDiaryDate, dto.getDiaryDate());
        EmotionDiary diary = diaryMapper.selectOne(qw);
        LocalDateTime now = LocalDateTime.now();
        if (diary == null) {
            // 当天还没有 → 新建
            diary = EmotionDiary.builder()
                    .userId(userId)
                    .diaryDate(dto.getDiaryDate())
                    .moodScore(dto.getMoodScore())
                    .dominantEmotion(dto.getDominantEmotion())
                    .emotionTriggers(dto.getEmotionTriggers())
                    .diaryContent(dto.getDiaryContent())
                    .sleepQuality(dto.getSleepQuality())
                    .stressLevel(dto.getStressLevel())
                    .createdAt(now)
                    .updatedAt(now)
                    .build();
            diaryMapper.insert(diary);
        } else {
            // 当天已有 → 覆盖更新（保留 id、createdAt）
            diary.setMoodScore(dto.getMoodScore());
            diary.setDominantEmotion(dto.getDominantEmotion());
            diary.setEmotionTriggers(dto.getEmotionTriggers());
            diary.setDiaryContent(dto.getDiaryContent());
            diary.setSleepQuality(dto.getSleepQuality());
            diary.setStressLevel(dto.getStressLevel());
            diary.setUpdatedAt(now);
            diaryMapper.updateById(diary);
        }
        return diary;
    }

    /** 管理端：分页查询情绪日志 */
    public Page<EmotionDiary> adminPage(EmotionDiaryAdminPageQuery query) {
        LambdaQueryWrapper<EmotionDiary> qw = new LambdaQueryWrapper<>();
        if (query.getUserId() != null) qw.eq(EmotionDiary::getUserId, query.getUserId());
        if (query.getStartDate() != null) qw.ge(EmotionDiary::getDiaryDate, query.getStartDate());
        if (query.getEndDate() != null) qw.le(EmotionDiary::getDiaryDate, query.getEndDate());
        qw.orderByDesc(EmotionDiary::getDiaryDate);
        return diaryMapper.selectPage(new Page<>(query.getPageNum(), query.getPageSize()), qw);
    }

    /** 管理端：删除情绪日志 */
    public void adminDelete(Long id) {
        if (diaryMapper.selectById(id) == null) {
            throw new BusionessException("情绪日志不存在");
        }
        diaryMapper.deleteById(id); // ai_analysis_task 若有外键 ON DELETE CASCADE 会级联删除
    }
}
```

**原理（幂等 upsert）**
1. 先按 `(userId, diaryDate)` 查当天记录。
2. **查不到 → insert**；**查得到 → 覆盖字段后 updateById**。
3. 这样做的好处：用户一天多次提交不会产生多条脏数据，前端也不用记"今天是新建还是编辑"。
4. 数据库层的 `unique(user_id, diary_date)` 是双保险——万一并发两个请求同时 insert，唯一键会拒绝第二条。
5. 更新时**刻意不覆盖** `id`、`createdAt`，只更新业务字段和 `updatedAt`。

**`adminPage` 的条件拼接**：三个 `if` 只有参数非空才拼对应 `WHERE`，实现"任意组合筛选"（按用户、按日期区间，或都不传查全部）。

# 三、快速自测清单

1. **咨询记录**
   - 普通用户登录 → `session/start` 建会话 → `stream` 聊两轮
   - `GET /api/psychological-chat/sessions` → 返回数组，只会看到自己的会话
   - `GET /api/psychological-chat/sessions/session_1/messages` → 按时间正序返回消息
   - `GET /api/psychological-chat/session/session_1/emotion` → 首次调 AI（慢），24h 内再调秒回
   - `DELETE /api/psychological-chat/sessions/session_1` → 再查消息应为空
2. **情绪日志**
   - `POST /api/emotion-diary` 提交当天日记 → 返回带 id
   - **同一天再提交一次** → 返回**同一个 id**（是更新不是新增）
   - 管理员 `GET /api/emotion-diary/admin/page?startDate=2026-09-01&endDate=2026-09-30` → 能按区间筛
   - 普通用户访问管理端接口 → 403
3. **权限**：普通用户带别人的 `sessionId` 查消息/情绪 → 应返回"无权操作该会话"
